# blog_studio 크롬 확장

내 AI 키로 블로그 글을 만들고, 네이버 블로그 글쓰기 화면에 채우는 크롬 확장 프로그램.
설계 문서는 `../docs/extension/`에 있다. 먼저 `START-HERE.md`를 읽는다.

## 빌드와 시험

```bash
npm install
cp .env.example .env   # 처음 한 번. 서버 주소와 공개용 키를 채운다
npm run build
npm run prompts
npm test
```

- `.env`에는 blog_studio 서버(Supabase)의 주소와 공개용 키, 그리고 blog_studio 웹의 주소(`WXT_WEB_URL`)를 넣는다. 웹 주소는 메일의 링크로 로그인할 때 쓴다. 웹의 `web/.env.local`에 있는 `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`와 같은 값을 써도 된다. 없이 빌드하면 로그인 없이 파일로만 프롬프트를 불러올 수 있다.
- `npm run keys:push`는 `web/.env.local`의 네이버 키(`NAVER_*`) 다섯 개를 서버의 `shared_keys` 표에 올린다. 가족이 함께 쓰는 키다. 키를 바꿨을 때 다시 한다. 표는 `supabase/migrations/018_shared_keys.sql`이 만든다.
- `npm run prompts:push`는 프롬프트 묶음을 만들어 서버에 올린다. 웹의 프롬프트나 `scripts/extension-prompts.ts`를 고친 뒤에 한다. 관리용 키는 `web/.env.local`에서 읽는다.
- 묶음에는 있어도 되고 없어도 되는 글이 있다 (`cards.rewrite`: 카드 문구를 AI로 다듬는 프롬프트. 웹의 `web/lib/cards-parser.ts`에서 가져온다). 서버의 묶음이 예전 것이면 카드는 만들어지지만 AI로 다듬지는 못한다.

- `npm run prompts`는 프롬프트를 읽어 `prompt-pack/blog-studio-prompts.json` 묶음 파일을 만든다. 웹의 프롬프트나 `scripts/extension-prompts.ts`를 고친 뒤에는 다시 만들고, 확장의 설정 탭에서 다시 불러온다.
- 묶음에는 형식 번호가 있다 (지금은 2). 확장이 바뀌어 번호가 오르면 예전 묶음은 쓸 수 없다. 다시 만들어 불러온다.
- `npm test`는 빌드한 파일을 쓴다. 그래서 빌드를 먼저 한다.
- `npm run zip`은 다른 사람에게 주거나 스토어에 올릴 압축 파일을 만든다 (`dist/blog-studio-extension-<버전>-chrome.zip`).
- `npm run store:assets`는 아이콘(`public/icon/`)과 스토어용 화면 사진(`store/`)을 다시 그린다. 이 컴퓨터의 크롬을 창 없이 띄워 미리보기 화면을 찍는다. 빌드를 먼저 한다.
- 결과는 `dist/chrome-mv3/` 폴더에 생긴다.

## 크롬에 넣기

1. 크롬 주소창에 `chrome://extensions`를 입력한다.
2. 오른쪽 위의 **개발자 모드**를 켠다.
3. **압축해제된 확장 프로그램을 로드합니다**를 누르고 `dist/chrome-mv3` 폴더를 고른다.
4. 코드를 고쳐서 다시 빌드한 뒤에는, 같은 화면에서 이 확장의 새로고침 버튼을 누른다.

이렇게 넣은 확장은 폴더의 위치가 곧 이름표다. 폴더를 옮기거나 확장을 삭제하면 저장해 둔 AI 키, 말투, 만든 글이 사라진다.
다른 사람에게 줄 때는 `npm run zip`으로 만든 압축 파일을 준다. 받은 사람은 풀어서 같은 방법으로 넣는다.

크롬 웹 스토어에 올리면 버튼 한 번으로 설치하고 새 버전도 알아서 바뀐다. 준비물과 순서는 `store/README.md`에 있다.

## 처음 쓸 때

1. **설정** 탭에서 blog_studio 웹과 같은 계정으로 로그인한다. 프롬프트를 서버에서 받아 온다.
   - 메일로 로그인: 이메일을 적고 [메일로 로그인 링크 받기]를 누른 뒤, **이 크롬에서** 메일의 링크를 누른다. 확장이 그 탭에서 로그인 정보를 받아 가고, 탭은 "확장에 로그인됐어요" 화면으로 바뀐다. 비밀번호가 필요 없다.
   - 다른 브라우저나 휴대폰에서 링크를 눌렀다면 확장이 받지 못한다. 메일을 다시 받고, "링크를 눌러도 로그인되지 않을 때"에 링크의 주소를 복사해 붙여넣는다.
   - 비밀번호를 알면 "비밀번호로 로그인하기"를 써도 된다. 로그인한 뒤 같은 카드에서 비밀번호를 새로 정할 수 있다.
   - 프롬프트를 받으려면 서버의 허락 목록(`prompt_access`)에 있어야 한다. 넣는 방법은 `supabase/migrations/017_prompt_packs.sql`의 머리에 있다.
   - 서버를 쓸 수 없으면 같은 카드의 "파일로 불러오기"에서 `prompt-pack/blog-studio-prompts.json`을 고른다.
2. **설정** 탭에서 쓸 AI의 키를 붙여넣고 [확인]을 누른다. 쓸 모델을 고른다.
3. 네이버 키는 로그인하면 서버에서 받아 온다 (가족이 함께 쓰는 키. 설정 탭의 "네이버 API 키"에 "서버에서 받아 쓰고 있어요"라고 나온다). 따로 쓰고 싶으면 같은 칸에 직접 넣는다. 그러면 **자료** 탭에서 키워드의 검색 수, 블로그 글, 뉴스를 찾을 수 있다. 쓸 키워드와 참고할 글을 고르고 [글쓰기에 넣기]를 누르면 글쓰기 탭에 채워진다.
3-1. (선택) **내 말투** 탭에서 내 블로그의 글을 모으고 [말투 정리하기]를 누른다. 네이버 블로그를 연 탭이 있어야 한다.
4. **글쓰기** 또는 **SEO 8단계** 탭에서 글을 만든다. SEO 8단계는 "한 단계씩"과 "한 번에 끝까지" 중에서 고른다.
   - 제품 리뷰는 **사진 리뷰** 탭에서 만든다. 내가 찍은 사진을 고르고 (10장까지, 고른 순서가 사진 번호), 제품 이름과 메모(가격, 산 곳, 좋았던 점, 아쉬운 점)를 적고 [리뷰 글 만들기]를 누른다. AI가 사진을 보고 글을 쓰고, 사진이 들어갈 자리(`[IMG: 사진1 - …]`)를 글 속에 정한다. [채우기로 보내기]를 누르면 글과 사진이 함께 채우기 탭으로 간다.
   - AI는 사진에 보이는 것과 메모에 적은 것만 사실로 쓴다. 알 수 없는 내용은 "확인 필요"로 남기니 채우기 전에 고친다.
5. [채우기로 보내기]를 누른다. 사진을 넣으려면 **채우기** 탭의 "사진"에서 이미지 자리마다 사진을 고른다 (본문에 `[IMG: 설명]` 줄이 있는 곳이 자리다).
   - 카드를 넣으려면 같은 탭의 "블로그용 카드 만들기"를 연다. 카드 모양을 고름 (작은 그림을 누른다. 만든 뒤에 바꿔도 된다) → [카드 만들기] → 카드의 글을 읽고 고침 → 카드들 아래의 [카드를 글에 넣기]. 본문에 카드 자리(`[IMG: 카드1 - …]`)가 생기고 카드 그림이 그 자리의 사진이 된다.
   - 카드의 글자는 확장에 넣어 둔 Pretendard로 그린다. 어느 컴퓨터에서나 같은 모양이다.
6. 네이버 글쓰기 화면을 연 탭에서 [채우기]를 누른다. 글을 채운 뒤 사진을 올려 자리에 넣는다. 그동안 글쓰기 탭을 보고 있어야 한다.

## 크롬에 설치하지 않고 화면 보기 (개발용)

```bash
npm run build
npm run preview
```

`http://localhost:4179`에서 사이드 패널 화면이 열린다. 확장 기능은 가짜로 흉내 내고, AI는 미리 적어 둔 답을 돌려준다.
주소 뒤에 `?pack=1&keys=1`을 붙이면 프롬프트 묶음과 가짜 키가 들어간 상태로 열린다. `&blog=1`을 더 붙이면 네이버 블로그 탭이 열려 있는 것처럼 꾸민다 (가짜 글 목록). `&slow=1`은 AI의 답을 천천히 보낸다. 네이버 화면에 채우는 것은 여기서 볼 수 없다.

## 지킬 것

- 발행 버튼은 코드로 누르지 않는다.
- 사진은 사람이 고른 파일과 확장이 그린 카드만 올린다. 인터넷에서 사진을 가져오지 않는다.
- 카드의 숫자는 본문과 같아야 한다. 본문에 없는 숫자가 카드에 있으면 카드 아래에 알려 준다. AI로 문구 다듬기는 기본으로 꺼 둔다. 카드에서 색이나 형광펜으로 돋보이게 하는 숫자도 제목과 본문에 있는 숫자뿐이다.
- 카드 모양은 직접 만든 것만 쓴다. 다른 프로그램의 카드 모양이나 서체 파일을 가져오지 않는다. 글씨체는 누구나 쓸 수 있게 공개된 Pretendard(OFL 1.1)만 넣고, 사용 허락 글을 같이 둔다.
- 사진 리뷰의 사진과 메모는 사용자가 [리뷰 글 만들기]를 눌렀을 때, 사용자가 고른 AI 회사로만 보낸다. 긴 쪽 1280픽셀로 줄인 사본을 보낸다. 서버(Supabase)에는 올리지 않는다.
- 리뷰 글은 사진에 보이는 것과 메모에 적은 것만 사실로 쓰게 한다. 겪지 않은 일을 지어내게 하지 않는다. 제품이나 대가를 받았으면 글 첫머리에 밝히게 한다.
- 프롬프트 글을 `entrypoints/`와 `lib/`에 적지 않는다. 묶음 파일로만 주고받는다. `tests/leak.test.ts`가 확인한다.
- AI 키는 요청 헤더에만 넣는다. 주소, 오류 글, 기록에 넣지 않는다.
- 네이버 API 키는 패키지와 저장소(GitHub)에 넣지 않는다. 암호화해서 넣더라도 푸는 열쇠가 같이 들어가서 소용이 없다. 가족이 함께 쓰는 키는 서버의 `shared_keys` 표에 두고, 프롬프트를 받을 수 있는 사람(`prompt_access`)만 로그인해서 받는다. 확장에서 직접 넣은 키는 서버로 보내지 않는다.
- 네이버 키는 요청 헤더에만 싣는다. 검색광고의 비밀키는 서명을 만드는 데만 쓴다. 검색광고 키는 그 광고 계정을 다루는 데도 쓸 수 있으니, 받을 수 있는 사람을 가족으로만 둔다.
- 로그아웃하거나 받을 수 없는 계정이 되면, 서버에서 받아 둔 공용 키는 이 컴퓨터에서 지운다.
- 네이버 API는 읽는 것만 부른다 (글 찾기, 키워드 조회). 찾은 글은 제목과 요약만 받는다. 본문을 긁어 오지 않는다.
- 페이지에서 읽어 온 글자를 화면에 넣을 때는 `textContent`만 쓴다.
- 접근 허용 주소는 `blog.naver.com`, 네이버 API 두 곳(`openapi.naver.com`, `api.searchad.naver.com`), AI 3사의 API 주소, blog_studio 서버 주소, blog_studio 웹 주소뿐이다. 모든 사이트 접근 권한을 요청하지 않는다. `tests/leak.test.ts`가 확인한다.
- 웹 주소의 탭에서는 주소만 본다. 확장에서 로그인 메일을 요청하고 기다리는 중일 때만, 주소에 붙어 온 로그인 정보를 받는다. 화면의 내용은 읽지 않는다.
- 확장에는 서버의 공개용 키만 넣는다. 관리용 키(service role)는 넣지 않는다. `tests/leak.test.ts`가 확인한다.
- 비밀번호와 메일 코드는 요청에만 쓰고 저장하지 않는다. 로그인 메일을 요청할 때 새 계정을 만들지 않는다.
- 네이버 블로그에서는 읽기만 한다. 로그인 정보를 싣지 않고 공개 글만 읽는다. 내 블로그의 글만 모은다.
- 내 글과 말투 카드는 이 컴퓨터에만 둔다. 말투를 정리할 때만 사용자가 고른 AI로 보낸다.
- 웹의 글쓰기 코드나 프롬프트를 고치면 `npm test`를 돌린다. 확장과 달라지면 `tests/parity.test.ts`가 알려 준다.
