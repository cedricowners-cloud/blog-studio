## 지금 상태

- 2026-11-16: 개발을 시작했다. 작업 브랜치는 `feat/chrome-extension`이다. 아직 커밋하지 않았다.
- 확장은 `blog_studio/extension/`에 있다. 빌드와 설치 방법은 `extension/README.md`에 있다.
- **E0**: 뼈대와 사이드 패널을 만들었다. 로그인은 넣지 않았다. E1~E3은 DB 없이 진행하므로 E4에서 넣는다.
- **E1**: 에디터를 읽는 코드를 만들었고, **실제 네이버 글쓰기 화면에서 읽히는 것을 확인했다** (에디터 1.78.1). 확인한 내용은 `EDITOR-NOTES.md`에 있다.
- 견본: 굵게·글자 크기·정렬·표·사진까지 넣은 견본을 받아 `extension/fixtures/`에 뒀다 (git에는 올리지 않는다). 형식은 `EDITOR-NOTES.md`에 정리했다.
- **E2, E3**: 글 채우기를 만들었고, **실제 네이버 화면에서 채워지는 것을 사용자가 확인했다.** 채운 글을 다시 읽은 문서도 넣은 것과 같았다. 인용구 6종과 구분선 8종을 모두 쓸 수 있다.
- **색 강조** (확장 0.2.0): `[pos]` 긍정, `[neg]` 부정, `[mark]` 형광펜. 색은 패널의 "색 설정"에서 정한다. 실제 네이버 화면에서 색으로 보이는 것까지 사용자가 확인했다.
- **글쓰기와 SEO 8단계** (확장 0.3.0): 확장 안에서 내 AI 키로 글을 만든다. 글쓰기 방식 6개와 SEO 8단계를 웹과 같은 프롬프트로 돌린다. 만든 글은 [채우기로 보내기]로 채우기 탭에 넘긴다.
  - 웹 폴더는 고치지 않았다. 웹의 글쓰기 코드를 확장 폴더에 옮겨 적었고, 웹과 같은 결과가 나오는지 시험이 확인한다 (`DESIGN-detail.md` 5.2).
  - 프롬프트는 확장 패키지에 넣지 않았다. `npm run prompts`로 만든 묶음 파일을 설정 탭에서 한 번 불러온다 (`DESIGN-detail.md` 5.3).
  - AI 키는 설정 탭에서 넣는다. [확인]을 누르면 쓸 수 있는 모델 목록을 받아 온다.
  - 화면은 탭 네 개다: 글쓰기, SEO 8단계, 채우기, 설정.
- 아직 확인하지 못한 것:
  - **진짜 AI 키로 글이 만들어지는지.** AI 호출은 가짜 서버로만 시험했다. Gemini, OpenAI, Claude에 보내는 요청의 모양이 실제와 맞는지는 처음 쓸 때 확인해야 한다.
  - 크롬에 설치한 확장에서 묶음 파일을 고르는 창이 잘 뜨는지 (미리보기에서는 파일 창을 시험하지 못했다).
  - 임시저장한 글을 다시 열어도 그대로인지. 사용자가 시험이 잘 됐다고 했지만, 다시 열어 본 것인지는 듣지 못했다.

## 지킬 것

1. **발행 버튼은 코드로 누르지 않는다.** 임시저장은 선택 기능을 켰을 때만 한다.
2. **기존 폴더는 필요한 만큼만 고친다.** `web`에는 설계 문서에 적힌 것만 더한다. `local_agent`와 `jobs` 표는 건드리지 않는다.
3. **다른 확장 프로그램의 코드, 프롬프트 문장, 서체는 가져오지 않는다.** 구조만 참고했다. 에디터 부품 모양은 내 에디터에서 직접 읽은 견본으로 만든다.
4. **프롬프트는 확장 파일에 넣지 않는다.**
5. **커밋은 요청받았을 때만 한다.**

## 폴더 위치

- 이 프로젝트는 `~/dev/blog_studio`에 있다. 2026-11-16에 iCloud가 동기화하는 문서 폴더에서 옮겼다.
- 예전 위치(`문서/00_project/...`)를 가리키는 메모나 설정이 남아 있으면 새 위치로 고친다.
- `~/dev`는 iCloud에 올라가지 않는다. 백업은 GitHub로 한다.
- 파이썬 가상환경(`venv`)은 폴더를 옮기면 깨진다. 로컬 에이전트를 다시 쓸 때는 가상환경을 새로 만든다.
- 코드 프로젝트를 문서 폴더나 데스크탑에 두지 않는다. iCloud가 `node_modules`와 git 내부 파일까지 올리고, 저장 공간 최적화가 파일을 이 맥에서 지울 수 있다.
