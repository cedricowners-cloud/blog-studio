# 블로그 뉴스 도우미 (가칭) — MVP 설계 문서

작성일: 2026-11-15
버전: v0.1 (설계 단계, 코드 없음)

---

## 0. 한 줄 요약

**뉴스 기사 몇 개를 고르면 사실만 뽑아서 내 말투로 네이버 블로그 정보글을 새로 쓰고, 네이버 글쓰기 화면에 채워 주는 크롬 확장 프로그램.**
발행 버튼은 사람이 누른다.

### 정해진 조건

| 항목 | 결정 |
|---|---|
| 사용자 | 나와 가족 (몇 명). 판매하지 않는다 → 로그인·결제·서버 없음 |
| 글 종류 | 뉴스 정보글 하나만 |
| AI | Gemini · Claude · GPT 셋 다 쓸 수 있고, 각자 자기 API 키를 넣는다 |
| 발행 | 자동으로 하지 않는다. 채우기까지만 하고 사람이 확인한 뒤 누른다 |

### 참고한 것

데이폴리의 `BLOG AI HELPER` v0.3.3을 분석한 결과를 바탕으로 했다. **구조와 원리만 참고한다.** 그쪽 코드, 프롬프트 문장, 서체, 음악은 가져오지 않고 전부 새로 쓴다.

## 1. 범위

### MVP에 넣는 것
1. 구글 뉴스에서 분야별·검색어별로 기사 목록 불러오기
2. 기사 1~3개를 골라 본문 가져오기
3. **1단계: 사실 정리표 만들기.** AI가 기사에서 사실만 JSON으로 뽑는다. 사람이 고치거나 지울 수 있다.
4. **2단계: 원고 쓰기.** 사실 정리표만 보고 쓴다. 원문 기사는 AI에게 주지 않는다.
5. **자동 검사.** 분량, 키워드 횟수, 정리표에 없는 숫자, 원문과 겹치는 문장, 출처 표기, 단정 표현을 확인한다.
6. **네이버에 넣기.** (a) 복사 후 붙여넣기 방식을 먼저 만들고, (b) 자동 채우기를 그다음에 만든다.
7. 설정: AI 키 3개, 기본 AI와 모델, 다른 AI로 넘어가는 순서, 말투 예시, 맺음말, 기본 분량
8. 최근 원고 20개 기록
9. 오늘 AI를 몇 번 호출했는지 세기

### MVP에서 빼는 것 (2단계에서 추가)
- 카드뉴스·썸네일 이미지 생성 (선택 과제로 M7에 썸네일 1장만 둔다)
- 체험단 후기, 쇼핑커넥트, 여행 글
- 예약 발행, 자동 발행 (이건 앞으로도 하지 않는다)
- 로그인, 결제, 사용량 서버

## 2. 사용 흐름

```
[사이드 패널 열기]
   │
   ▼
① 뉴스 탭: 분야 선택(경제/IT/건강/생활…) 또는 검색어 입력
   │  → 구글 뉴스 RSS에서 목록 표시 (제목 · 언론사 · 시간)
   │  → 기사 1~3개 체크
   ▼
② [사실 정리] 버튼
   │  → 고른 기사를 숨은 탭에서 하나씩 열어 본문 추출
   │  → AI 1차 호출: 사실 정리표(JSON)
   │  → 화면에 표로 보여줌. 틀린 줄 삭제, 직접 한 줄 추가 가능
   ▼
③ 원고 옵션: 메인 키워드 · 함께 쓸 키워드 · 분량 · 관점/메모 · 말투 · 사용할 AI
   │
   ▼
④ [원고 쓰기] 버튼
   │  → AI 2차 호출: 사실 정리표 + 옵션 → 원고(JSON)
   │  → 자동 검사 실행 → 결과 배지 (통과 ✅ / 경고 ⚠️)
   │  → 미리보기: 제목 후보 3개, 소제목, 문단, 해시태그, 출처
   │  → [다시 쓰기] / [이 문단만 다시] / 직접 수정
   ▼
⑤ 네이버 블로그 글쓰기 탭을 연다
   │  → [네이버에 채우기]   (자동, M6b)
   │  → [복사하기] → 에디터에 Ctrl/Cmd+V   (안전한 대체 방법, M6a)
   ▼
⑥ 사람이 확인하고 직접 발행
```

## 3. 화면 (사이드 패널)

탭 4개: **뉴스 · 원고 · 기록 · 설정**

### 뉴스 탭
- 분야 칩: 주요 · 경제 · IT/과학 · 건강 · 생활 · 연예 · 스포츠
- 검색창과 기간 선택 (24시간 / 7일)
- 기사 카드: 체크박스, 제목, 언론사, 몇 시간 전, 원문 열기 링크
- 하단 고정: "선택 2/3 · [사실 정리]"

### 원고 탭
- **사실 정리표**: 접을 수 있는 표 (사실 / 숫자 / 발언 요지 / 아직 모르는 점 / 기사끼리 어긋나는 점). 줄마다 삭제 버튼이 있고 "+ 직접 추가"가 있다.
- **옵션**: 키워드, 분량(기본값 1,500~2,000자), 관점 메모, 말투 프리셋, AI 선택 드롭다운
- **결과**: 제목 후보(라디오 버튼), 본문 미리보기, 검사 결과 목록(경고를 누르면 해당 문장이 강조됨)
- **버튼**: [다시 쓰기] [네이버에 채우기] [복사하기]

### 기록 탭
- 최근 원고 20개: 제목, 날짜, 사용한 AI. 누르면 다시 열린다.

### 설정 탭
- AI 키 3개 (가려서 표시, [확인] 버튼으로 실제 호출 테스트)
- 기본 AI, AI별 모델, 실패 시 넘어갈 순서
- 말투: 내 글 예시 붙여넣기 (최대 2,000자), 문체 메모
- 맺음말 (매 글 끝에 고정으로 붙일 문장), 기본 분량
- 오늘 사용량 (AI별 호출 수)
- 설정 내보내기/가져오기 (JSON 파일, **키는 빼고**) → 가족끼리 말투나 맺음말 공유용

## 4. 기술 구조

### 4.1 스택
- **WXT** (크롬 확장용 Vite 기반 프레임워크) + **TypeScript**
- 화면: Preact 또는 순수 TS (번들을 작게 유지)
- AI SDK: 공식 SDK 3개 (§6 참고)
  - Claude: `@anthropic-ai/sdk`
  - OpenAI: `openai`
  - Gemini: `@google/genai`
- 스키마 검증: `zod` (AI 응답 검증과 Claude의 구조화 출력에 같이 쓴다)

### 4.2 파일 구성 (예정)

```
blog-ai-mvp/
├─ wxt.config.ts            # manifest 설정
├─ entrypoints/
│  ├─ background.ts         # 아이콘 클릭 시 사이드 패널 열기
│  └─ sidepanel/            # 화면 (index.html, main.ts, tabs/*)
├─ lib/
│  ├─ news/rss.ts           # 구글 뉴스 RSS → Article[]
│  ├─ news/extract.ts       # 숨은 탭에서 본문 추출
│  ├─ ai/
│  │  ├─ types.ts           # 공통 인터페이스
│  │  ├─ gemini.ts | claude.ts | openai.ts
│  │  ├─ router.ts          # 기본 AI → 실패 시 다음 AI
│  │  └─ repair.ts          # 깨진 JSON 복구
│  ├─ prompts/
│  │  ├─ extract-facts.ts   # 1단계 프롬프트
│  │  └─ write-draft.ts     # 2단계 프롬프트 (블록 조립 방식)
│  ├─ schema.ts             # zod 스키마: Article, FactSheet, Draft, Settings
│  ├─ checks/               # 자동 검사 6종
│  ├─ naver/
│  │  ├─ to-html.ts         # Draft → 붙여넣기용 HTML
│  │  └─ fill.ts            # MAIN world에서 실행할 에디터 채우기 함수
│  └─ storage.ts            # chrome.storage 래퍼, 사용량 카운터
└─ DESIGN.md
```

### 4.3 manifest 권한

| 권한 | 이유 |
|---|---|
| `sidePanel` | 사이드 패널 화면 |
| `storage`, `unlimitedStorage` | 설정, 키, 원고 기록 저장 |
| `scripting` | 기사 본문 추출, 네이버 에디터 채우기 |
| `activeTab` | 사용자가 버튼을 누른 탭에만 접근 |
| `host_permissions` | `news.google.com`, `blog.naver.com`, `generativelanguage.googleapis.com`, `api.anthropic.com`, `api.openai.com` |
| `optional_host_permissions: <all_urls>` | 언론사 사이트의 본문을 읽기 위해. 처음 [사실 정리]를 누를 때 한 번 허락받는다 |

- 키는 `chrome.storage.local`에 저장하고 `setAccessLevel({accessLevel: "TRUSTED_CONTEXTS"})`로 웹페이지 쪽에서는 읽을 수 없게 막는다.
- 서버 없음. 분석·추적 도구 없음.

## 5. 데이터 형식 (zod 스키마의 기준)

```ts
Article = {
  id: string;            // url 해시
  title: string;
  source: string;        // 언론사
  url: string;           // 최종 언론사 주소 (구글 뉴스 주소 아님)
  publishedAt: string;   // ISO
  text: string;          // 본문 (최대 8,000자로 자르지 말고, 길면 사용자에게 알림)
}

FactSheet = {
  issue: string;                         // 한 문장 요약
  category: "경제"|"IT"|"건강"|"생활"|"기타";
  facts:   { id: string; text: string; by: string; asOf: string; sourceId: string }[];
  numbers: { id: string; label: string; value: string; unit: string; asOf: string; by: string }[];
  quotes:  { speaker: string; gist: string }[];   // 그대로 옮기지 않은 요지
  unknowns:  string[];   // 아직 확인 안 된 점
  conflicts: string[];   // 기사끼리 다른 점
}

Draft = {
  titleCandidates: [string, string, string];
  intro: string;
  sections: { heading: string; paragraphs: string[] }[];
  outro: string;
  hashtags: string[];               // 5~10개
  usedFactIds: string[];            // 근거로 쓴 사실 id
  omitted: string[];                // 근거가 부족해서 뺀 내용
  sources: { title: string; source: string; url: string }[];   // 코드가 채운다 (AI가 만들지 않음)
}

Settings = {
  provider: "gemini"|"claude"|"openai";
  fallbackOrder: ("gemini"|"claude"|"openai")[];
  models: { gemini: string; claude: string; openai: string };
  keys:   { gemini?: string; claude?: string; openai?: string };
  length: { min: number; max: number };       // 공백 제외 글자 수
  voiceSample: string;  voiceNote: string;  signature: string;
}
```

**원칙:**
- `sources`(출처)는 AI에게 쓰게 하지 않는다. 코드가 Article 정보로 채운다. AI가 출처를 지어내는 것을 막기 위해서다.
- 사실·숫자에 붙는 id는 코드가 매긴다. 원고는 `usedFactIds`로 근거를 밝힌다.

## 6. AI 연결 설계

### 6.1 공통 인터페이스

```ts
interface AiProvider {
  id: "gemini" | "claude" | "openai";
  listModels(key): Promise<string[]>;       // 설정 화면의 "모델 불러오기"
  testKey(key, model): Promise<boolean>;    // 아주 짧은 시험 호출
  generateJSON<T>(req: {
    system: string;
    user: string;
    schema: ZodSchema<T>;
    purpose: "extract" | "write";           // 단계마다 다른 설정을 쓴다
    signal: AbortSignal;                    // [중지] 버튼
  }): Promise<{ data: T; usage: Usage; model: string }>;
}
```

`router.ts`의 동작:
1. 기본 AI로 호출한다.
2. 429(한도 초과), 5xx, 네트워크 오류가 나면 지수 백오프로 2번 재시도한다.
3. 그래도 실패하면 `fallbackOrder`의 다음 AI(키가 있는 것만)로 넘어간다.
4. 넘어갔다는 사실을 화면에 표시한다.
5. 400(요청 오류)과 키 오류는 넘어가지 않고 바로 알려준다.

### 6.2 AI별 메모

**Gemini** (`@google/genai`)
- JSON 응답 모드와 응답 스키마를 지정해 호출한다.
- 모델은 하드코딩하지 않는다. 데이폴리 코드에도 "목록에는 있지만 신규 사용자에게 막힌 모델"이 있었다. 그래서 **목록을 불러온 뒤 시험 호출로 실제 되는 모델을 고른다.**
  - 참고: 2026-11 데이폴리 코드의 시험 순서는 `gemini-3.6-flash`, `gemini-3.5-flash` 순이었다.
- 무료 한도가 있으므로 가족 기본값으로 둔다. 호출 수는 직접 센다(구글 기준 날짜).

**Claude** (`@anthropic-ai/sdk`)
- 기본 모델: `claude-opus-5-5`. 설정에서 `claude-sonnet-5-5`나 `claude-haiku-5-5`로 바꿀 수 있다.
- 확장 프로그램 안에서 직접 부르므로 클라이언트 생성 시 `dangerouslyAllowBrowser: true`를 준다. 키는 사용자 본인 것이고 본인 기기에만 있다.
- 구조화 출력은 `client.messages.parse()`에 `output_config.format: zodOutputFormat(schema)`를 쓴다. `parsed_output`이 null이면 repair 후 재시도한다.
- 생각 강도는 `output_config.effort`로 조절한다. Opus 5.5의 기본값은 medium이라 명시적으로 지정한다.
  - 사실 추출: `low`
  - 원고 쓰기: `medium` (품질을 보고 `high`로 올릴지 정한다)
  - Opus 5.5는 생각 기능을 끌 수 없다. `thinking: disabled`를 보내면 400이 난다.
- 원고는 길게 나올 수 있으니 스트리밍과 `finalMessage()`를 쓰고, `max_tokens`는 넉넉히 준다.
- 안전 분류 때문에 답이 거절되는 경우(`stop_reason: "refusal"`)를 처리한다. 서버 쪽 대체 기능(`fallbacks: "default"`, 베타 `server-side-fallback-2026-07-01`)을 켜 두고, 거절이 나면 화면에 이유를 보여준다.
- 대략 비용(추정): 글 1편당 입력 약 1.5만, 출력 약 0.6만 토큰 기준으로 Opus 5.5에서 200~300원 정도.

**OpenAI** (`openai`)
- Responses API에 JSON 스키마 구조화 출력을 쓴다. 브라우저에서 부르므로 `dangerouslyAllowBrowser: true`를 준다.
- 모델 ID는 설정에서 목록을 불러와 고른다.
  - 참고: 2026-11 데이폴리 코드는 `gpt-6-luna`를 썼다.

### 6.3 JSON 안전장치
- 모든 응답을 zod로 검증한다. 실패하면:
  1. `repair.ts`로 고친다 (코드블록 표시 제거, 끝에 남은 쉼표 제거, 첫 번째로 짝이 맞는 `{…}`만 남기기).
  2. 그래도 실패하면 "형식 오류 내용 + 원래 응답"을 주고 한 번만 다시 요청한다.

## 7. 프롬프트 설계 원칙

문장은 직접 새로 쓴다. 아래는 담아야 할 **규칙**이다.

### 1단계: 사실 정리 (extract)
- 기사에서 사실만 뽑는다. 기자의 해석, 전망, 평가는 뺀다.
- 숫자는 단위, 기준 시점, 발표 주체(기관·회사)와 함께 적는다. 언론사는 발표 주체가 아니다.
- 원문 문장을 옮기지 않고 짧게 바꿔 적는다. 발언은 요지만 적는다.
- 기사끼리 다르면 둘 다 적고 `conflicts`에 표시한다. 없는 내용은 채우지 않는다.

### 2단계: 원고 쓰기 (write)
프롬프트는 **블록을 조립하는 방식**으로 만든다. 순서대로:
1. 오늘 날짜
2. 사실 정리표
3. 관점/메모
4. 키워드
5. 분량
6. 말투
7. 구성
8. 금지 사항
9. 출력 형식

- 사실 정리표에 없는 숫자, 날짜, 발언은 쓰지 않는다. 일반적인 배경 설명은 써도 된다.
- 숫자를 쓸 때는 "○○부가 11월 14일 발표한 기준으로"처럼 발표 주체와 시점을 문장 안에 넣는다.
- 요약이 아니라 **해설**을 쓴다. 왜 생겼는지, 읽는 사람에게 어떤 영향이 있는지 쓴다. 확인된 것과 아직 모르는 것을 나눠 쓴다.
- 글쓴이의 체험을 지어내지 않는다 ("제가 써보니" 같은 문장 금지). 말투 예시 속 내용도 가져오지 않는다.
- 키워드: 메인 키워드는 본문에 4~5번, 함께 쓸 키워드는 각각 1~2번. 넣으려고 사실을 지어내지 않는다.
- 분량: 공백 제외 `min~max`자. 서론 15%, 본론 70%, 결론 15%.
- 건강·금융 주제에는 주의 문구를 넣는다 ("개인 상황에 따라 다르니 전문가와 상담"). 단정 표현을 쓰지 않는다.
- 말투 예시는 **문체만** 참고한다.

## 8. 자동 검사 (`checks/`)

원고가 나오면 코드가 바로 검사한다. AI를 부르지 않는다.

| # | 검사 | 방법 | 결과 |
|---|---|---|---|
| 1 | 분량 | 제목, 소제목, 공백을 빼고 글자 수를 센다 | 범위를 벗어나면 ⚠️ |
| 2 | 키워드 횟수 | 메인 4~5번, 나머지 1~2번 | 모자라거나 넘치면 ⚠️ |
| 3 | 근거 없는 숫자 | 원고의 숫자(%, 원, 명, 날짜 등)를 정리표의 숫자와 대조 | 없는 숫자가 있으면 ⚠️ + 해당 문장 강조 |
| 4 | 원문과 겹침 | 원고와 원문 기사 사이에 **공백 제외 20자 이상 같은 구간**이 있는지 | 있으면 ⚠️ + 해당 구간 강조 (저작권 보호용) |
| 5 | 출처 표기 | 숫자가 있는 문장에 발표 주체나 시점이 있는지 (간단한 규칙) | 없으면 ℹ️ |
| 6 | 단정 표현 | "무조건", "반드시 오른다", "완치" 같은 목록과 대조 | 있으면 ⚠️ |

경고가 있어도 진행할 수 있다. 판단은 사람이 한다.

## 9. 네이버에 넣기

### 9.1 M6a: 복사 후 붙여넣기 (먼저 만든다, 안정적)
- Draft를 단순한 HTML로 바꾼다. 소제목은 `<h3>` 또는 굵은 글씨, 문단은 `<p>`, 구분선은 `<hr>`, 맨 끝에 출처 목록을 붙인다.
- `navigator.clipboard.write`로 `text/html`과 `text/plain`을 같이 복사한다.
- 사용자가 에디터 본문을 클릭하고 붙여넣는다. 제목은 [제목 복사] 버튼으로 따로 복사한다.
- 장점: 네이버 내부 구조에 의존하지 않아서 잘 깨지지 않는다.

### 9.2 M6b: 자동 채우기 (그다음, 편하지만 깨질 수 있음)

원리 (BLOG AI HELPER를 분석해서 확인한 것):
- 스마트에디터 ONE은 화면 HTML이 아니라 **내부 문서 데이터(JSON)**를 저장한다. innerHTML로 넣으면 화면에는 보여도 저장되지 않는다.
- 에디터는 `iframe#mainFrame` 안에 있다. 그래서 `chrome.scripting.executeScript({ target: {tabId, allFrames: true}, world: "MAIN", func })`로 실행한다.
- 페이지에 있는 에디터 객체에서 문서 데이터를 꺼내 내용을 바꾸고 다시 넣는다.
  - 순서: 문서 데이터 읽기 → 제목 칸의 글자만 바꾸기 → 본문 부품(text, quotation, horizontalLine) 만들기 → 다시 넣기
- 이 방식은 **네이버가 공개한 기능이 아니다.** 그래서 다음을 지킨다:
  1. 실행 전에 에디터 객체와 필요한 함수가 있는지 확인한다. 없으면 즉시 M6a 방식으로 안내한다.
  2. 기존 글이 있으면 덮어쓰기 전에 확인을 받는다.
  3. 이미 들어 있는 쇼핑커넥트나 지도 같은 특수 부품은 건드리지 않는다.
  4. 저장이나 발행은 절대 누르지 않는다.
- 이미지는 MVP에서 넣지 않는다. 2단계에서 붙여넣기 이벤트 방식으로 추가한다.

## 10. 가족에게 나눠 쓰기

| 방법 | 장점 | 단점 |
|---|---|---|
| **A. 압축 해제 설치** (개발자 모드) | 바로 가능, 비용 없음 | 업데이트할 때마다 폴더를 바꿔 줘야 함. 크롬이 개발자 모드 경고를 띄움 |
| **B. 웹스토어 "일부 공개(Unlisted)"** | 링크를 아는 사람만 설치 가능, 자동 업데이트 | 개발자 등록비(1회), 심사 대기 |

- 추천: 처음에는 A로 쓰다가 안정되면 B로 옮긴다.
- 키는 각자 자기 키를 넣는 것을 추천한다. Gemini는 구글 계정마다 무료 한도가 따로 있다. 한 사람의 키를 같이 쓰면 한도와 요금이 한 사람에게 몰린다.
- 말투와 맺음말은 "설정 내보내기/가져오기"로 공유한다. 내보낼 때 키는 빠진다.

## 11. 개발 순서 (마일스톤)

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| **M0** 뼈대 | WXT 프로젝트, 사이드 패널, 설정 저장 | 아이콘을 누르면 패널이 열리고, 설정이 새로고침 후에도 남아 있음 |
| **M1** 뉴스 목록 | RSS 불러오기와 파싱, 분야/검색 | 분야 7개와 검색어로 목록이 10초 안에 뜸 |
| **M2** 본문 추출 | 숨은 탭으로 언론사 페이지 열기 → 본문 뽑기 (아래 메모 참고) | 주요 언론사 10곳 중 8곳 이상에서 300자 넘는 본문을 추출 |
| **M3** AI 연결 | 어댑터 3개, 키 확인, router, repair | 3사 모두 같은 스키마의 JSON을 돌려주고, 기본 AI 키를 틀리게 넣으면 다음 AI로 넘어감 |
| **M4** 원고 생성 | 1단계 → 정리표 편집 → 2단계 → 미리보기 | 기사 3개로 원고 1편이 2분 안에 나옴 |
| **M5** 자동 검사 | 검사 6종과 강조 표시 | 일부러 숫자를 바꾼 원고에서 3번 검사가 잡아냄 |
| **M6a** 복사 넣기 | HTML 복사 | 네이버 에디터에 붙여넣으면 소제목과 문단 모양이 유지됨 |
| **M6b** 자동 채우기 | MAIN world에서 에디터 채우기 | 채운 뒤 임시저장하고 다시 열어도 내용이 그대로 있음 |
| **M7** (선택) 썸네일 | 캔버스로 제목 카드 PNG 1장 → 복사 | 1080×1080 이미지가 만들어짐 |
| **M8** 가족 배포 | 압축 해제 설치 안내서 1장 | 가족 1명이 안내서만 보고 설치하고 글 1편을 씀 |

**M2 메모:** 구글 뉴스 RSS의 기사 링크는 그냥 불러오면 구글 뉴스 화면이 올 뿐이고, 브라우저가 자바스크립트를 실행해야 언론사로 넘어간다. 그래서 숨은 탭을 쓴다.
- 기사마다 탭을 새로 만들고 다 쓰면 닫는다. 탭 하나를 돌려 쓰면 이전 기사 본문이 섞일 수 있다.
- 주소가 언론사로 넘어가고 본문이 300자를 넘을 때까지 0.5초 간격으로 확인하고, 최대 20초 기다린다.
- 안 되면 대체 방법을 쓴다: 사용자가 기사를 직접 연 탭에서 [이 탭에서 가져오기]

### 품질 확인용 테스트 세트
- 분야별로 2개씩, 뉴스 주제 10개를 고정한다.
- AI를 바꾸거나 프롬프트를 고칠 때마다 10개를 다시 돌린다.
- 기록할 것: 검사 경고 수, 분량 적중, 사람이 매긴 점수(1~5).

## 13. 2단계 후보 (MVP 이후)
1. 원고 내용으로 카드뉴스 이미지 5~10장 만들기 (캔버스 렌더링) + 붙여넣기 이벤트로 사진 넣기
2. 네이버 검색 API(뉴스)를 두 번째 뉴스 출처로 추가 (원문 링크를 바로 받을 수 있지만, 키 발급이 필요함)
3. "이 문단만 다시 쓰기"를 대화형으로
4. 내 템플릿 읽기 (에디터의 기존 틀을 읽어 칸 지정)
5. 체험단 후기 모드 (데이폴리 앱 사용 흐름과 연결)
