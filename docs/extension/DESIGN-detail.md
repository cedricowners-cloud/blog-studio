## 0. 한 줄 요약

**blog_studio의 글쓰기와 발행을 크롬 확장 하나로 할 수 있게 한다.**
확장에서 내 AI 키로 글을 만들고, 내 말투를 입히고, 네이버 글쓰기 화면에 버튼 하나로 채운다. 주제를 쌓아 두면 자리를 비운 동안 글을 만들어 둔다. 발행·예약 버튼은 사람이 누른다.

### v0.2에서 바뀐 것

| 항목 | v0.2 | v0.3 |
|---|---|---|
| 확장의 역할 | 발행만 | 발행 + 글쓰기 + 내 말투 |
| AI 호출 | 확장에서 하지 않음 | 확장이 사용자의 키로 직접 호출 |
| AI 키 | 확장에 두지 않음 | 확장(내 PC)에만 보관. 발급 안내 화면 추가 |
| 프롬프트 | 서버에만 있음 | 서버에 두고, 로그인한 확장이 받아 씀 |
| 말투 | 다루지 않음 | 내 글에서 말투 카드를 만들어 적용 |

발행 부분(4장)은 v0.2와 같다.

### v0.4에서 더한 것

다른 사람이 쓴 블로그 자동화 안내 글(Claude Code와 로봇 브라우저로 임시저장까지 하는 방식)을 보고 가져온 6가지다. 한 줄씩 타이핑하는 방식 자체는 가져오지 않았다.

| 2 | 글마다 검수 카드 | 5.8 |
| 3 | 간단 모드 (주제, 독자 상황, 한줄 메모) | 5.7 |
| 4 | 다음 글에도 적용되는 "내 규칙" | 5.9 |
| 5 | "작성 중인 글" 팝업 감지, 실패한 단계부터 이어 하기 | 4.2 |
| 6 | 가족용 안내서 형식 (소요 시간, 자주 막히는 곳 표, 운영 수칙) | 10장 |

| # | 더한 것 | 위치 |
|---|---|---|
| 1 | 글감 대기열: 주제를 여러 개 넣어 두면 차례로 글을 만들어 쌓아 둔다 | 5.10 |
| 2 | 자동 임시저장: 준비된 글을 네이버 임시저장함까지 넣어 둔다. **선택 기능이고 기본은 꺼져 있다** | 5.11 |

### 정해진 것

| 항목 | 결정 |
|---|---|
| 기반 | 기존 `blog_studio` (웹 + Supabase) |
| 발행 | 크롬 확장. 로컬 에이전트는 지우지 않되 손대지 않는다 |
| 예약 발행 | 네이버 발행 창의 "예약" 기능. 사람이 선택한다 |
| 글쓰기 | 확장에서도 할 수 있게 한다 (섞는 방식, 5장) |
| 자리를 비운 동안 | 글감 대기열로 글을 만들어 쌓아 둔다 |
| 자동 임시저장 | 선택 기능으로 둔다. 기본은 꺼짐. 공개 발행은 어떤 경우에도 자동으로 하지 않는다 |
| AI 비용 | 각자 자기 키를 쓴다. 확장이 키 발급을 안내한다 |
| 말투 | 각자 자기 글로 말투 카드를 만든다 |
| 사용자 | 나와 가족. 각자 로그인해서 자기 블로그를 운영한다 |
| 글 종류 | 기존 업무용 정보글 (증여·상속, 기업 정부지원자금·융자) |
| 자료 수집 | 상속세 계산기와 공고 크롤러는 쓰지 않는다. 확장이 열린 페이지를 가져온다 |

### 성공 기준 (바뀌지 않음)

> 소제목·인용구·구분선·표가 들어간 실제 글을 확장으로 채우고, **임시저장한 뒤 다시 열어도 내용과 서식이 그대로**면 성공이다.

글쓰기와 말투는 이 기준을 통과한 다음에 붙인다.

## 1. 지금 구조와 바뀌는 부분

```
[지금]
웹(Vercel) ──▶ Supabase jobs 큐 ◀── 로컬 에이전트(내 PC, 로봇 브라우저)
  글 생성(서버가 AI 호출)             └─ 에디터에 한 글자씩 타이핑, 글 1건당 15분

[바뀐 뒤]
                    ┌──────────── Supabase ────────────┐
                    │ 로그인 · 프롬프트 · 업종 설정      │
                    │ 글 보관 · 말투 카드 · 발행 묶음     │
                    └───▲──────────────────────▲──────┘
                        │                      │
   웹(Vercel)  ─────────┘                      └───── 크롬 확장(사이드 패널)
   키워드·순위·통계·업종 편집                         글쓰기 ──▶ AI (내 키로 직접 호출)
   8단계 SEO 글쓰기, 이미지 준비                       내 말투
                                                     발행 ──▶ 네이버 글쓰기 탭에 채움
```

| 영역 | 지금 | 바뀐 뒤 |
|---|---|---|
| 글 생성 | 웹에서만 (서버가 AI 호출) | 웹에서도, 확장에서도 |
| AI 키 | DB에 저장 (암호화 없음) | 확장 사용자는 내 PC에만 저장 |
| 말투 | "작성자 페르소나" 칸에 직접 적기 | 내 글에서 자동으로 뽑아 채움 |
| 발행 | 로컬 에이전트 | 크롬 확장 |
| 이미지 | 발행 때 이미지 자리가 지워짐 | 자리에 맞춰 들어감 |
| 표 | 지원 안 됨 | 표로 들어감 |
| 키워드, 순위 추적, 통계, 업종 편집 | 웹 | 웹 그대로 |
| 8단계 SEO 글쓰기 | 웹 | 웹에서도, 확장에서도 (2026-11-16에 바꿈. 5.12) |

### 하지 않는 것
- 확장이 발행 버튼을 대신 누르는 일
- 사람 없이 공개로 발행하는 일 (임시저장까지만 선택으로 허용한다, 5.11)
- 서로이웃·좋아요·댓글 자동화
- 다른 사람 블로그의 말투를 본뜨는 일

## 2. 사용 흐름

**A. 확장에서 쓰고 바로 발행 (가족이 주로 쓰는 길)**
```
① 확장 [글쓰기]: 글쓰기 방식, 주제, 키워드, 말투를 고른다
② (선택) 공고·안내 페이지를 열고 [이 탭을 자료로 추가]
③ [글 만들기] → 내 키로 AI 호출 → 검증 → 미리보기
④ 네이버 글쓰기 화면을 열고 [채우기]
⑤ 눈으로 확인하고, 발행 창에서 태그와 발행 시간(지금/예약)을 정해 직접 발행
```

**B. 웹에서 쓰고 확장으로 발행 (공들여 쓰는 길)**
```
① 웹에서 키워드 조사, 8단계 SEO 글쓰기, 이미지 준비
② 웹 글 상세 화면에서 [확장으로 보내기]
③ 확장 [발행]에서 글을 고르고 [채우기] → 이후는 A의 ⑤와 같음
```

**C. 주제를 쌓아 두고 나중에 발행 (자리를 비우는 날)**
```
① 주제를 여러 개 대기열에 넣는다 (확장에서, 또는 폰으로 웹에서)
② 자리를 비운 동안 글이 차례로 만들어져 "발행 대기"에 쌓인다
③ (자동 임시저장을 켰다면) 준비된 글이 네이버 임시저장함에도 들어간다
④ 돌아와서 확인필요에 답하고, 한 편씩 확인해서 발행하거나 예약한다
```

세 길 모두 글은 같은 곳(Supabase)에 저장되고, 발행은 사람이 한다.

## 3. 확장 화면 (사이드 패널)

탭 4개: **글쓰기 · 발행 · 내 말투 · 설정**

### 첫 실행 안내 (3단계)
1. 로그인 (blog_studio 계정)
2. AI 키 넣기 (Gemini 추천, 6장)
3. 네이버 글쓰기 화면에서 시험 글 채워 보기

### 글쓰기 탭
- **간단 모드 (기본)**: 주제, 독자 상황, 한줄 메모만 적는다 (5.7)
- **자세히 모드**: 글쓰기 방식(6종), 업종, 메인 키워드, 서브 키워드, 독자 단계를 직접 고른다
- 말투 선택 (내 말투 카드 또는 기본)
- 자료: [이 탭을 자료로 추가], 직접 붙여넣기
- 실제 사례 메모 (비워 두면 경험담을 쓰지 않음)
- 사용할 AI와 예상 비용
- [글 만들기] → 진행 표시 → 미리보기
- **검수 카드**: 글자 수, 제목 길이, 키워드 횟수, 어긴 규칙, 확인필요 목록 (5.8)
- 확인필요 항목에 하나씩 답하기
- [다시 쓰기], [이 수정을 다음 글에도 적용], [발행으로 보내기]
- [대기열에 넣기]: 지금 만들지 않고 글감 대기열에 쌓아 둔다 (5.10)
- 대기열 보기: 기다리는 주제, 만드는 중, 끝난 것, 실패한 것. [대기열 실행], [멈춤]

### 발행 탭
- 발행 대기 글 목록 (상태: 확인 필요, 준비됨, 임시저장됨), 최근 발행한 글
- 글 상세: 본문 미리보기, 이미지 자리, 태그와 [태그 복사]
- **[채우기]**, [복사하기] (대체 방법)
- 확인필요 표시가 남은 글은 [채우기]가 꺼져 있다
- 에디터 상태: 글쓰기 화면인지, 에디터를 찾았는지, 써 둔 글이나 "작성 중인 글" 팝업이 있는지
- 채우다 실패하면 어느 단계에서 멈췄는지 보여 주고 [이어 하기]를 제공한다

### 내 말투 탭
- 말투 카드 목록 (예: 정보글용, 일상글용)
- 예시 글 추가: [이 글을 말투 예시로 추가], 직접 붙여넣기
- [말투 분석] → 말투 카드 보기·고치기
- 내 규칙: 다음 글부터 계속 적용할 메모 보기·고치기 (5.9)

### 설정 탭
- AI 키 안내 카드 3개 (6장)
- 기본 AI, 오늘 사용량
- 글감 대기열: 글을 만드는 곳(확장 또는 서버), 하루에 만드는 글 수 상한
- 자동 임시저장 (선택, 기본 꺼짐): 켜기, 하루 상한, 안내문
- 로그아웃, 에디터 견본 다시 읽기

## 4. 발행 설계 (v0.2와 같음)

### 4.1 블록 목록 (본문의 하나뿐인 형식)

지금은 본문이 `[h2]…[/h2]` 같은 마크업 글자로 저장되고, 글마다 형식이 달라 어긋나는 일이 있었다. 바뀐 뒤에는 **한 번 변환한 블록 목록(JSON)을 확정 저장**하고, 채우기는 그것만 받아 쓴다.

```ts
type Run = { text: string; bold?: boolean; italic?: boolean; underline?: boolean };

type Block =
  | { kind: "heading";   level: 2 | 3; text: string }
  | { kind: "paragraph"; runs: Run[]; align?: "left" | "center" | "right" }
  | { kind: "quote";     style: 1 | 2 | 3; runs: Run[] }
  | { kind: "divider";   style: 1 | 2 | 3 }
  | { kind: "table";     rows: string[][]; headerRow: boolean }
  | { kind: "image";     slot: string; alt: string };
```

| 지금 마크업 | 블록 | 에디터에서의 모양 |
|---|---|---|
| `[h2]…[/h2]` | heading 2 | 글자 크기 24 + 굵게 (지금과 같음) |
| `[h3]…[/h3]` | heading 3 | 글자 크기 19 + 굵게 (지금과 같음) |
| `[bold]` `[italic]` `[underline]` | paragraph의 run | 굵게, 기울임, 밑줄 |
| `[quote]` `[quote2]` `[quote3]` | quote 1·2·3 | 인용구 기본, 라인, 말풍선 |
| `[hr]` `[hr2]` `[hr3]` | divider 1·2·3 | 구분선 3종 |
| `[center]` `[right]` | paragraph의 align | 가운데, 오른쪽 정렬 |
| 마크다운 표 | table | 표 (새로 지원) |
| `[IMG: 섹션1 - 설명]` | image (slot = "섹션1") | 이미지 (새로 지원) |

변환기는 공용 코드(5.2)에 한 벌만 둔다. 웹과 확장이 같은 코드를 쓴다.

### 4.2 에디터에 채우기

**원리**
- 네이버 스마트에디터는 화면의 글자가 아니라 내부 문서 데이터를 저장한다. 에디터가 가진 문서 데이터를 꺼내 바꾼 뒤 다시 넣는다.
- 에디터는 페이지 안의 프레임 속에 있다. 확장은 글쓰기 탭의 모든 프레임에서, 페이지와 같은 실행 환경으로 스크립트를 돌린다.
- 이 방식은 **네이버가 공개한 기능이 아니다.** 네이버가 에디터를 바꾸면 고쳐야 할 수 있다.

**부품 모양은 "견본을 본떠서" 만든다**
- 소제목, 인용구, 구분선, 표의 데이터 모양을 추측해서 만들지 않는다.
- 손으로 각 요소를 하나씩 넣은 견본 글을 에디터에서 읽어 저장한다.
- 채울 때는 견본 부품을 복사해 글자만 바꾼다.
- 네이버가 모양을 바꾸면 견본만 다시 읽으면 된다.

**채우는 순서**
1. 에디터를 찾고 필요한 기능이 있는지 확인한다. 없으면 멈추고 [복사하기]를 안내한다.
2. "작성 중인 글이 있습니다" 팝업이 떠 있으면 멈추고 알려 준다. 이어 쓸지 새로 쓸지는 사람이 고른다.
3. 이미 써 둔 글이 있으면 덮어쓸지 묻는다.
4. 제목 칸의 글자를 바꾼다.
5. 블록 목록을 에디터 부품으로 바꿔 본문에 넣는다. 이미지 자리에는 표시용 문단을 둔다.
6. 결과를 다시 읽어 블록마다 글자를 대조한다. 빠지거나 순서가 바뀐 곳이 있으면 어디인지 알려 준다.
7. 이미지를 올리고 자리로 옮긴다 (4.3).
8. 이미지까지 넣은 결과를 한 번 더 확인한다.

**이어 하기**
- 어디까지 채웠는지(글, 이미지)를 발행 묶음에 기록한다.
- 중간에 실패하면 실패한 단계부터 다시 한다. 글이 잘 들어갔으면 이미지 단계만 다시 한다.
- 글 자체를 다시 만들지 않는다.

**건드리지 않는 것**: 지도·쇼핑·스티커 같은 특수 부품, 발행 버튼. 저장 버튼은 자동 임시저장을 켰을 때만 누른다 (5.11)

**대체 방법: 복사하기**
- 블록 목록을 단순한 HTML로 바꿔 클립보드에 넣고, 사용자가 본문에 붙여넣는다.
- 네이버 내부 구조에 의존하지 않아서 채우기가 고장 났을 때도 쓸 수 있다.

### 4.3 이미지

**과정**
1. 자리마다 이미지를 정한다 (웹의 "이미지 준비" 화면).
2. 이미지 파일을 Supabase Storage의 비공개 폴더에 올린다.
3. 확장이 채우기를 할 때 파일을 내려받는다.
4. 확장이 파일을 에디터에 붙여넣은 것처럼 넣는다. 네이버가 자기 서버에 업로드한다.
5. 업로드가 끝나면 각 이미지를 표시용 문단 자리로 옮긴다.
6. 발행이 끝나면 Storage의 파일은 지워도 된다.

| 종류 | 준비 방법 | 지금 있는 것 |
|---|---|---|
| 카드 이미지 | 섹션 내용으로 카드를 그려 PNG로 저장 | 카드 만들기, 1080×1080 내보내기 |
| 무료 사진 | 자리 설명으로 검색해서 고름 | Unsplash·Pixabay 검색 |
| AI 생성 이미지 | 자리 설명으로 생성 | 생성 기능 |
| 내 사진 | 파일 올리기 | 없음 (추가) |

**안전장치**
- 파일 이름으로 짝을 맞춘다. 넣은 순서를 믿지 않는다.
- 올라가지 않은 이미지는 최대 2번 다시 넣고, 그래도 빠지면 빈 자리를 알려준다.
- 탭이 뒤로 가면 업로드가 멈출 수 있다. 다시 보일 때까지 기다렸다가 이어서 한다.
- 이미지를 올리기 전의 문서를 보관해 두고, 서식이 흐트러지면 보관본에 이미지만 끼운다.

**블로그용 카드 (기존 카드 기능에 크기 설정 추가)**

| 설정 | 크기 | 쓰는 곳 |
|---|---|---|
| 인스타 (지금 있음) | 1080×1080 | 인스타 카드뉴스 묶음 |
| 블로그 썸네일 | 1080×1080 | 글 맨 위 대표 이미지 |
| 블로그 본문 | 가로형 (비율은 13장에서 정함) | 섹션마다 1장: 요약, 비교표, 절차 |

- 카드 속 금액·비율·날짜는 본문의 값과 같아야 한다. 카드를 만들 때 코드로 대조한다.
- "AI가 문장을 다시 쓰기" 옵션은 블로그 본문 카드에서는 기본으로 끈다.

**첫 버전에서 실제로 만든 것 (2026-11-18, 확장 0.6.0. 실제 화면에서는 아직 확인하지 못함)**

- 사진은 **내 컴퓨터의 파일**에서 고른다. 채우기 탭에서 본문의 이미지 자리(`[IMG: 설명]`)마다 사진을 골라 두면, 글을 채운 뒤 그 자리에 넣는다. 서버의 Storage는 아직 쓰지 않는다 (로그인으로 글을 주고받게 될 때 붙인다).
- 고른 사진은 사이드 패널에서 다듬어서 보낸다: 긴 쪽이 2000픽셀을 넘으면 줄이고, 다시 그리면서 촬영 위치 같은 정보(EXIF)가 빠진다. 움직이는 GIF는 그대로 보낸다. 한 장에 8MB까지.
- 넣는 순서는 설계와 같다: 붙여넣기 → 올라오기를 기다림 → 자리 옮기기. 자리 옮기기는 "붙여넣기 전의 문서에 사진 부품만 끼워 넣기"로 한다 (`EDITOR-NOTES.md`의 사진 넣기).
- 사진이 올라오지 않은 자리는 글자로 남기고 알려 준다. [사진만 넣기]로 사진 단계만 다시 할 수 있다 (글을 다시 채우지 않는다).
- 아직 없는 것: AI로 만든 이미지, 무료 사진 찾기, 사진 설명글(캡션), AI 표시(`ai` 값), 여러 장을 나란히 넣기.

**블로그용 카드로 실제로 만든 것 (2026-11-18, 확장 0.7.0. 미리보기에서 확인함. 실제 화면에 올리는 것은 아직 확인하지 못함)**

- 채우기 탭의 "블로그용 카드 만들기"에서 만든다. 표지 카드 1장(글 맨 위, 대표 사진)과 소제목마다 요약 카드 1장이다. 본문에 소제목이 없으면 표지만 만든다. 웹의 목록 카드와 마무리 카드는 블로그에서는 쓰지 않는다.
- 카드의 내용은 웹과 같은 코드로 만든다: `web/lib/cards-parser.ts` → `extension/lib/cards/parser.ts`. 웹은 고치지 않았고, 같은 결과가 나오는지 `tests/parity.test.ts`가 견준다.
- 그림은 사이드 패널의 캔버스에 직접 그린다 (`lib/cards/render.ts`). 모양은 웹의 카드 미리보기를 따랐다. 처음에는 그 컴퓨터의 서체로 그렸고, 0.9.0부터 확장에 넣은 Pretendard로 그린다. 글이 길면 글자를 조금씩 줄여서 칸에 맞춘다.
- 크기는 만들 때 고른다: 정사각형 1080×1080, 가로형 1200×900. 색은 색 설정의 긍정 강조 색, 아래의 작은 글은 적어 둔 브랜드 이름이다.
- 자리: [카드를 글에 넣기]를 누르면 본문에 `[IMG: 카드0 - …]`(표지, 맨 위)과 `[IMG: 카드N - …]`(소제목 바로 아래)이 들어간다 (`lib/cards/slots.ts`). 다시 넣으면 예전 카드 자리는 지우고 새로 넣는다. 사람이 넣어 둔 다른 이미지 자리와 그 자리에 골라 둔 사진은 그대로 둔다.
- 카드 그림은 PNG로 만들어 사진 자리에 넣고, 올리는 것은 위의 사진 넣기와 같은 길을 쓴다.
- 0.7.1: [카드를 글에 넣기] 버튼과 그 안내는 만들어진 카드들 아래에 둔다 (사용자 의견). 카드의 문구를 만들 때는 본문의 이미지 자리(`[IMG: …]`)를 빼고 읽는다. 카드를 넣은 뒤 다시 만들어도 자리 표시가 카드에 찍히지 않는다. 소제목 아래 문장이 하나뿐이면 설명 칸을 비운다 (같은 문장이 두 번 찍히지 않게).
- 숫자 대조: 카드에 있는데 제목과 본문에 없는 숫자를 카드 아래에 알려 준다. 숫자를 통째로 견준다 (본문의 "5,000만"으로 카드의 "50%"를 넘어가지 않는다). 막지는 않고 알려 주기만 한다.
- AI로 문구 다듬기는 설계대로 기본으로 끈다. 켜면 웹과 같은 프롬프트로 한 번 묻고, 빠뜨린 카드가 있으면 한 번 더 묻는다. 실패하면 본문의 문장을 그대로 쓴다. 프롬프트는 묶음의 `cards.rewrite`로 받는다. 이 글은 없어도 되는 글이라 예전 묶음도 그대로 쓸 수 있다 (그때는 다듬기만 못 한다).
- 0.8.0: 카드 모양을 여덟 가지로 늘렸다 (사용자 의견: 카드가 투박하다). 만드는 칸 맨 위에서 작은 그림을 눌러 고르고, 카드를 만든 뒤에 바꿔도 된다 (고친 글은 그대로 남는다). 고른 모양은 저장된다. 처음 값은 "잡지".

  | 모양 | 생김새 |
  |---|---|
  | 잡지 | 큰 번호를 연하게 깔고, 핵심 문장을 색 상자에 넣는다 |
  | 색 띠 | 위쪽을 브랜드 색으로 채우고 소제목을 흰 글자로 쓴다. 숫자에 형광펜 |
  | 부드러운 상자 | 연한 바탕 위에 둥근 흰 상자. 핵심 문장 앞에 체크 표시 |
  | 진한 바탕 | 어두운 바탕에 흰 글자. 숫자는 노란색 |
  | 옆 번호 | 왼쪽에 색 기둥을 세우고 번호를 크게 쓴다 |
  | 메모지 | 종이 색 바탕과 테이프. 소제목과 숫자에 형광펜 |
  | 가운데 정렬 | 글을 가운데로 모으고 핵심 문장을 크게 쓴다 |
  | 기본 | 웹의 카드와 같은 예전 모양 |

  - 모든 모양은 브랜드 색 하나에서 나머지 색을 만들어 쓴다 (`mixColor`). 새 모양들은 글을 위아래 가운데에 놓고, 설명 글자를 40 안팎(1080 기준)으로 키웠다.
  - 숫자 강조: 핵심 문장의 숫자와 바로 붙은 단위("5,000만 원", "10년")를 색이나 형광펜으로 돋보이게 한다. **제목과 본문에 있는 숫자만** 강조한다 (`knownNumbers`). 본문에 없는 숫자는 돋보이게 하지 않고, 카드 아래에 따로 알려 준다.
  - 코드: `render.ts`(크기·색, 그림으로 만들기), `designs.ts`(모양 여덟 가지), `draw.ts`(줄바꿈, 숫자 나누기, 글·딱지·줄·상자 쌓기). 목록 카드와 마무리 카드는 블로그에서 쓰지 않아 기본 모양으로만 그린다.
- 0.9.0: 글씨체 Pretendard를 확장에 넣었다 (사용자 요청). `public/fonts/PretendardVariable.woff2` 하나에 모든 굵기가 들어 있다 (2MB). 사용 허락은 SIL Open Font License 1.1이고, 그 글을 같은 폴더에 둔다. `lib/cards/font.ts`가 카드를 그리기 전에 불러오고, 실패하면 컴퓨터의 서체로 그린다. 인터넷에서 받아 오지 않는다.
- 아직 없는 것: 비교표 카드와 절차 카드, 카드에 사진 깔기.

### 4.4 발행, 예약, 태그
- 발행 창은 사람이 연다. 확장은 [태그 복사]만 제공한다.
- 예약은 발행 창의 발행 시간에서 사람이 고른다.
- 바로 발행하면 탭 주소가 글 주소로 바뀔 때 확장이 주소와 시각을 저장한다.
- 예약하면 패널에서 [예약했어요]를 누르고 시간을 적는다.

### 4.5 인용구와 구분선의 종류 (2026-11-16 추가)

에디터에는 인용구가 6종, 구분선이 8종 있다. 기존 마크업은 3종씩만 쓰고 있었는데, 확장은 전부 받는다.

| 마크업 | 에디터 모양 |
|---|---|
| `[quote]` ~ `[quote6]` | 기본, 라인, 말풍선, 포스트잇, 모서리, 밑줄 |
| `[hr]` ~ `[hr8]` | `default`, `line1` ~ `line7` |

- 어느 종류를 어디에 쓸지는 AI가 글마다 고르게 두지 않는다. **사람이 "디자인 설정"에서 용도별로 정한다.** 글마다 모양이 달라지면 블로그가 어수선해 보인다.
- 용도 예: 핵심 요약에는 포스트잇, 다른 사람의 말에는 라인, 섹션 사이에는 구분선 2번.
- AI는 용도만 표시한다 (예: 요약, 인용, 주의). 어떤 모양으로 넣을지는 설정이 정한다.

### 4.6 글자 색 강조 (2026-11-16 추가, 확장 0.2.0에 만듦. 실제 화면에서 확인함)

**색을 직접 적지 않고 뜻을 적는다.** 본문에는 "긍정 강조", "부정 강조" 같은 뜻만 표시하고, 실제 색은 사람마다 설정에서 정한다.

| 본문의 표시 | 뜻 | 실제 색 |
|---|---|---|
| `[pos]…[/pos]` | 긍정 강조 (혜택, 가능, 추천) | 내 브랜드 색 |
| `[neg]…[/neg]` | 부정 강조 (주의, 불가, 손해) | 빨강 계열 (바꿀 수 있음) |
| `[mark]…[/mark]` | 형광펜 (꼭 기억할 문장) | 배경색 |

- 이렇게 하면 가족마다 브랜드 색이 달라도 같은 글쓰기 규칙을 쓸 수 있고, 색을 바꿔도 글을 다시 만들지 않아도 된다.
- 브랜드 색의 기본값은 업종 설정에 이미 있는 카드 디자인의 대표색(`CardDesign.colors.primary`)에서 가져온다.
- 블록 목록에서는 글자 조각(Run)에 `tone`(positive, negative)과 `highlight`를 더한다. 채울 때 설정의 색으로 바꾼다.
- 글자색은 글자 조각의 `fontColor`, 형광펜은 `backgroundColor`에 넣는다. 내 에디터에서 저장되고 화면에 색으로 보이는 것까지 확인했다 (`EDITOR-NOTES.md`). 채운 뒤에는 색이 남았는지 다시 읽어서 견준다.
- 색 강조에는 굵게가 자동으로 붙는다. 형광펜에는 붙지 않는다.
- 색은 확장의 "색 설정"에서 정하고 이 컴퓨터에만 저장한다. 나중에 계정 설정으로 옮긴다.

**규칙**
- 색 강조는 굵게와 같이 쓴다. 색만으로 뜻을 전하지 않는다 (색을 구분하기 어려운 독자가 있다).
- 한 글에 색은 두세 가지까지만 쓴다.
- 색 강조는 문단마다 한 곳 이하로 한다. 많으면 강조가 아니게 된다. 검수 카드에서 개수를 센다.
- 설정에서 브랜드 색을 고를 때 흰 바탕에서 읽기 어려운 색이면 알려 준다 (명암 대비 확인).
- 긍정·부정 표시도 사실에 묶인다. 근거 없이 "무조건 가능" 같은 말을 색으로 강조하지 않는다.

## 5. 글쓰기 설계 (새로 추가)

### 5.1 섞는 방식

| 무엇을 | 어디에 두나 | 이유 |
|---|---|---|
| AI 호출 | 확장 (내 키로 직접) | 키가 내 PC 밖으로 나가지 않고, 서버 비용과 실행 시간 제한이 없다 |
| 프롬프트, 업종 설정 | 서버 (로그인하면 받음) | 확장 파일에 넣으면 설치한 사람 누구나 꺼내 볼 수 있다. 고쳐도 확장을 다시 배포하지 않아도 된다 |
| 만든 글, 검증 기록 | 서버 | 웹과 확장에서 같은 글을 본다 |
| 글쓰기 로직 | 공용 코드 | 웹과 확장의 결과가 같아야 한다 |

**알아 둘 점**: 로그인한 사람은 받아 온 프롬프트를 볼 수 있다. 누구에게 계정을 주느냐가 곧 프롬프트의 공개 범위다 (8장).

### 5.2 공용 코드

글쓰기 로직을 `web/lib/core/` 한 곳에 모으고, 확장이 그 폴더를 가져다 쓴다.

- 들어가는 것: AI 호출, 프롬프트 조립, 응답 해석, 검증, 재시도, 블록 변환, 비용 계산, 타입
- 조건: 브라우저에서도 도는 코드만 넣는다. 파일 읽기, 서버 전용 부품, `@/` 경로 별칭을 쓰지 않는다.
- 웹 폴더 안에 두는 이유: Vercel 배포 설정을 건드리지 않기 위해서다. 예전에 폴더 밖 파일을 연결했다가 배포에서 깨진 적이 있다.

지금 코드에서 고칠 곳:

| 파일 | 지금 | 바꿀 것 |
|---|---|---|
| `lib/ontology/prompt-builder.ts` | 프롬프트를 서버 파일에서 읽음 | 프롬프트 글을 인자로 받게 바꿈 |
| `lib/ontology/retry-loop.ts` 등 | `@/lib/...` 경로 사용 | 상대 경로로 바꿈 |
| `lib/llm.ts` | 서버 환경 변수의 키 사용, 예전 모델, `temperature` 항상 전송 | 키를 인자로 받음, 6.4의 수정 |
| `lib/naver.ts`, 스크래퍼 2개 | 서버 전용 부품 사용 | 옮기지 않음 (웹에 남김) |

**첫 버전에서 실제로 한 방식 (2026-11-16, 확장 0.3.0)**

웹 폴더는 고치지 않았다. 운영 중인 웹을 건드리지 않고 먼저 확장에서 글이 만들어지는지 보기 위해서다.

- 웹의 글쓰기 코드를 확장 폴더(`extension/lib/writer`, `lib/seo`, `lib/llm`)에 옮겨 적었다.
- 옮긴 코드가 웹과 같은 결과를 내는지는 시험(`extension/tests/parity.test.ts`)이 확인한다. 웹의 진짜 코드를 불러와 같은 입력을 넣고 결과를 글자 하나까지 견준다. 웹 코드나 프롬프트가 바뀌어 달라지면 시험이 실패한다.
- 확인하는 것: 방식 6개의 프롬프트 조립, 답 해석, 통과 조건 세기, 다시 쓰기 요청 글, SEO 8단계의 프롬프트와 순서
- 아직 옮기지 않은 것: 업종 설정을 프롬프트에 넣는 부분, 상위 글 조사, 공고 링크의 내용 가져오기, 비용 계산
- 코드가 두 곳에 있는 것은 임시다. 웹과 연결할 때(E4, G2) `web/lib/core/`로 합친다.

### 5.3 프롬프트와 업종 설정 받기
- 프롬프트(공통 + 방식 6종)를 DB의 `prompt_templates` 표로 옮긴다. `prompts/*.md`는 원본으로 두고, 올리는 스크립트를 둔다.
- 웹과 확장 모두 이 표에서 읽는다.
- 업종 설정은 이미 DB에 있어서 그대로 읽는다.
- 확장은 받은 프롬프트를 파일로 저장하지 않고, 쓰는 동안만 메모리에 둔다.

**서버에서 받기 (2026-11-17, 확장 0.5.0에 만듦. DB에 적용함)**

- 확장의 설정 탭에서 웹과 같은 이메일·비밀번호로 로그인하면, 프롬프트 묶음을 서버에서 받아 온다. 창을 열 때마다 새 묶음이 있는지 조용히 확인한다.
- 표는 설계의 `prompt_templates` 대신 두 개를 만들었다 (`supabase/migrations/017_prompt_packs.sql`).
  - `prompt_packs`: 묶음 전체를 JSON 한 줄(`default`)로 둔다. 방식별 글, SEO 단계별 글, 글 조각이 함께 맞아야 해서 따로 나누지 않았다.
  - `prompt_access`: 프롬프트를 받아도 되는 사람 목록 (사용자 번호).
- **이 프로젝트는 가입이 열려 있다** (2026-11-17 확인. 이메일만 있으면 누구나 계정을 만들 수 있다). 그래서 "로그인한 사람"이 아니라 "`prompt_access`에 있는 사람"만 읽게 했다. 로그인하지 않은 요청, 목록에 없는 사용자, 로컬 에이전트의 토큰으로는 읽히지 않는 것을 확인했다. 쓰기는 관리용 키로만 된다.
- 올리기: `extension` 폴더에서 `npm run prompts:push`. 묶음을 만들어 서버에 올린다. 관리용 키는 `web/.env.local`에서 읽는다.
- 사람 더하기: 그 사람이 웹에서 가입한 뒤, SQL 한 줄로 `prompt_access`에 넣는다 (SQL 파일 머리에 적어 둠).
- 받은 묶음은 이 컴퓨터의 확장 저장소에 둔다 (설계는 "메모리에만"이었다. 창을 열 때마다 다시 받지 않게 하려고 바꿨다). 대신 로그아웃하거나, 서버가 "받을 수 없는 사람"이라고 답하면 지운다.
- 웹은 아직 `web/prompts`의 파일을 읽는다. 웹도 이 표를 읽게 바꾸는 일은 남아 있다. 그때까지는 프롬프트를 고친 뒤 `npm run prompts:push`를 해야 확장에 반영된다.
- 서버 주소와 공개용 키는 `extension/.env`에 둔다 (git에 올리지 않는다. `.env.example` 참고). 관리용 키는 확장에 넣지 않는다. 패키지에 섞이지 않았는지 시험이 확인한다.

**파일로 불러오기 (2026-11-16의 첫 버전. 서버를 쓸 수 없을 때의 대체 방법으로 남겨 둠)**: "프롬프트 묶음" 파일을 한 번 불러온다.
- `extension` 폴더에서 `npm run prompts`를 하면 웹의 원본(`web/prompts/*.md`, `web/lib/seo-workflow.ts` 등)을 읽어 `extension/prompt-pack/blog-studio-prompts.json` 하나로 묶는다.
- 확장의 설정 탭에서 이 파일을 불러오면 이 컴퓨터의 확장 저장소에 들어간다.
- 묶음 파일은 확장 패키지에 넣지 않는다. 패키지에 프롬프트 글이 섞여 들어가지 않았는지는 시험(`tests/leak.test.ts`)이 확인한다.
- 묶음의 모양은 `prompt_templates` 표로 옮길 때 그대로 쓸 수 있게 했다 (방식별 글, SEO 단계별 글, 그 사이를 잇는 글 조각).

### 5.4 글 만드는 과정 (확장 안에서)
1. 입력을 모은다: 방식, 주제, 키워드, 독자 단계, 업종, 말투, 자료, 사례 메모
2. 프롬프트와 업종 설정을 받는다.
3. 공용 코드로 프롬프트를 조립한다.
4. 내 키로 AI를 직접 호출한다.
5. 응답을 해석하고 검증한다. 통과하지 못하면 정해진 횟수만큼 다시 시도한다.
6. 검수 카드를 만들고 확인필요 표시를 모은다 (5.8).
7. 글과 검증 기록, 토큰 사용량을 서버에 저장한다.
8. 블록 목록으로 변환해 발행 대기에 넣는다. 확인필요 표시가 남아 있으면 "확인 필요", 없으면 "준비됨" 상태가 된다.

- 글 생성은 사이드 패널 화면에서 돌린다. 생성 중에 패널을 닫으면 중단되므로 경고를 띄운다.
- 사례 메모가 비어 있으면 경험담을 쓰지 않게 한다. 지금 프롬프트는 "컨설팅 경험 언급 최소 2회"가 통과 조건이라 AI가 사례를 지어내기 쉽다. 이 조건을 "사례 메모가 있을 때만"으로 바꾼다.

### 5.5 자료 가져오기
- **[이 탭을 자료로 추가]**: 지금 열린 공고·안내 페이지의 본문을 읽어 자료로 넣는다.
- 어느 페이지를 자료로 쓸지는 사람이 고른다. 확장은 가져오기만 하고 맞는지 판단하지 않는다.
- HWP·PDF 첨부로만 올라온 공고는 읽지 못한다. 내용을 직접 붙여넣는다.
- 자료의 출처 주소와 가져온 날짜를 글과 함께 저장한다.

### 5.6 웹에 남는 기능
키워드 조회, 상위 글 조사, 순위 추적, 통계, 업종 편집, 이미지 준비, 카드 만들기

8단계 SEO 글쓰기는 웹에도 그대로 있고, 확장에서도 쓴다 (5.12).

### 5.7 간단 모드
- 입력은 세 가지다: **주제, 독자 상황**(누가 어떤 고민으로 검색하는지), **한줄 메모**(꼭 넣고 싶은 내용)
- 나머지는 자동으로 정한다. 글쓰기 방식은 지금 있는 방식 추천 기능이 고르고, 키워드는 주제에서 뽑아 보여 준 뒤 고칠 수 있게 한다.
- 업종과 말투는 지난번에 쓴 값을 기억한다.
- 자동으로 정한 값은 화면에 보여 주고, [자세히]를 누르면 직접 바꿀 수 있다.

### 5.8 확인필요 표시와 검수 카드

**확인필요 표시**
- 글쓰기 규칙에 넣는다: 입력과 자료에 없는 숫자, 날짜, 경험은 지어내지 말고 `[[확인필요: 무엇을]]` 표시를 단다.
- 글이 만들어지면 표시를 모아 목록으로 보여 준다. 사람이 하나씩 답한다: 값을 적어 넣기, 그 문장 지우기, 다시 쓰게 하기.
- **표시가 하나라도 남아 있으면 글은 "확인 필요" 상태로 남고, [채우기]가 꺼져 있다.** 모두 답하면 "준비됨"이 된다.
- 채우기 직전에 본문에 표시 글자가 남아 있는지 코드로 한 번 더 확인한다.

**검수 카드** (글마다 미리보기 위에 보여 준다)

| 항목 | 누가 확인하나 |
|---|---|
| 본문 글자 수, 제목 글자 수 | 코드가 센다 |
| 메인 키워드와 서브 키워드 횟수 | 코드가 센다 |
| 소제목 수, 이미지 자리 수, 태그 수 | 코드가 센다 |
| 확인필요 표시 목록 | 코드가 찾는다 |
| 글쓰기 방식의 통과 조건 | AI가 스스로 점검한 결과 (지금 있는 검증) |
| 어긴 규칙 | 위 결과를 모아 한눈에 보여 준다 |

- 코드가 센 값과 AI가 말한 값이 다르면 코드가 센 값을 믿는다.

### 5.9 내 규칙
- 사람마다 "내 규칙" 메모를 둔다. 예: "글자 수는 1,500자 안팎", "문단 사이에 빈 줄", "제목에 물음표를 쓰지 않기"
- 글을 만들 때마다 프롬프트에 넣는다.
- 글을 고친 뒤 **[이 수정을 다음 글에도 적용]**을 누르면 그 내용이 내 규칙에 더해진다. 누르지 않으면 그 글에만 적용된다.
- 우선순위는 사실 > 글 구조 > 내 규칙 > 말투다. 내 규칙이 글쓰기 방식의 통과 조건과 부딪히면 저장할 때 알려 준다.

### 5.10 글감 대기열

주제를 여러 개 넣어 두면 차례로 글을 만들어 "발행 대기"에 쌓아 둔다. 네이버는 건드리지 않는다.

**넣기**
- 확장의 [대기열에 넣기], 또는 웹의 대기열 화면에서 넣는다. 웹 화면은 폰에서도 쓰기 쉽게 만든다.
- 한 줄에 주제 하나씩 여러 개를 한 번에 넣을 수 있다. 독자 상황과 한줄 메모는 주제마다 적는다.

**글을 만드는 곳** (사람마다 설정에서 고른다)

| | 확장에서 만들기 | 서버에서 만들기 |
|---|---|---|
| AI 키 | 내 컴퓨터에만 있다 | 서버에 저장해야 한다 (지금 웹의 방식) |
| 조건 | 컴퓨터와 크롬이 켜져 있고, 확장 창이 열려 있어야 한다 | 없음. 컴퓨터가 꺼져 있어도 된다 |
| 폰으로 주제 넣기 | 넣을 수는 있고, 컴퓨터가 켜져 있을 때 만들어진다 | 넣으면 바로 만들어진다 |
| 맞는 사람 | 키를 서버에 두고 싶지 않은 사람 | 출근해서 폰으로 주제만 던지고 싶은 사람 |

**만드는 과정**
1. 대기열에서 주제를 하나 꺼낸다.
2. 최근 글과 주제가 겹치는지 본다. 겹치면 만들지 않고 "겹침"으로 표시한다.
3. 5.4와 같은 과정으로 글을 만든다.
4. 확인필요 표시가 없으면 "준비됨", 있으면 "확인 필요"로 발행 대기에 넣는다.
5. 하루 상한에 닿으면 멈춘다. 남은 주제는 다음 날 이어서 만든다.

**장치**
- 하루에 만드는 글 수 상한을 둔다 (기본값은 13장에서 정한다). AI 비용과 비슷한 글이 쏟아지는 것을 막는다.
- 한 편이 실패하면 그 주제만 "실패"로 두고 다음으로 넘어간다. 연달아 두 번 실패하면 대기열을 멈춘다.
- 끝나거나 멈추면 알림을 띄운다.

### 5.11 자동 임시저장 (선택 기능, 기본 꺼짐)

켜 두면, 준비된 글을 확장이 네이버 글쓰기 화면에 채우고 **임시저장까지** 해 둔다. 공개 발행은 하지 않는다.

**왜 선택 기능인가**
- 우리 방식은 채우기가 몇 초라서, 발행 대기에 쌓아 두는 것만으로도 충분하다. 임시저장함에 미리 넣어 두는 이점은 크지 않다.
- 사람 없이 네이버 화면을 조작하는 일은 계정에 부담이 될 수 있다. 저장 버튼을 누르는 부분은 네이버가 화면을 바꾸면 깨진다.
- 그래도 임시저장함에서 바로 확인하고 싶은 사람을 위해 선택으로 둔다.

**켤 때**
- 설정에서 직접 켠다. 켤 때 위 내용을 안내문으로 보여 주고 동의를 받는다.
- 하루 상한을 정한다 (기본 2건).

**동작**
1. "준비됨" 상태의 글만 대상이다. 확인필요 표시가 남은 글은 건너뛴다.
2. 확장이 새 탭으로 글쓰기 화면을 연다. 사용자가 쓰고 있던 탭은 쓰지 않는다.
3. 4.2의 순서대로 채우고, 블록마다 대조한다.
4. 대조가 맞으면 임시저장을 한다. E1에서 에디터에 저장 기능이 있는지 확인하고, 없으면 화면의 저장 버튼을 누른다.
5. 저장됐는지 확인한 뒤 탭을 닫고, 글 상태를 "임시저장됨"으로 바꾼다.
6. 한 편이 끝나면 일정 시간 쉬고 다음 글로 넘어간다.

**멈추는 조건** (멈추면 알림을 띄우고, 탭은 그대로 둔다)
- 네이버 로그인이 풀려 있다.
- "작성 중인 글이 있습니다" 팝업이 떴다. 자동으로 닫지 않는다. 쓰던 글이 사라질 수 있기 때문이다.
- 에디터를 찾지 못했거나 채운 내용이 대조와 다르다.
- 저장됐는지 확인하지 못했다.
- 하루 상한에 닿았다.

**하지 않는 것**
- 발행 버튼은 누르지 않는다. 이 기능의 코드에는 발행을 누르는 경로를 두지 않는다.
- 태그는 넣지 않는다. 네이버는 태그를 발행 창에서만 받는다. 발행할 때 [태그 복사]로 넣는다.
- 사람처럼 보이게 꾸미는 동작(일부러 느리게 타이핑하기 등)은 넣지 않는다.

**조건**
- 컴퓨터와 크롬이 켜져 있고, 네이버에 로그인돼 있고, 확장 창이 열려 있어야 한다.

| 6 | 제목과 설명 | 아니오 |
| 7 | 주소(URL). 자체 도메인에 올릴 때만 | 아니오 |
| 8 | 롱테일 키워드 (덤 단계) | 아니오 |

- 진행 방식 두 가지: AI와 바로 진행 (내 키), 프롬프트를 복사해서 다른 AI 화면에 붙여넣고 결과를 다시 붙여넣기
- 앞 단계의 결과가 다음 단계의 프롬프트 앞에 붙는다. 7단계는 6단계에서 고른 제목을 쓴다. 고르지 않으면 첫 번째 제목을 쓴다.
- 진행 상황은 이 컴퓨터의 확장 저장소에 둔다 (최근 20개). 창을 닫았다가 이어 할 수 있다. 로그인이 붙으면 서버로 옮긴다.
- 어느 단계의 결과든 [채우기로 보내기]로 채우기 탭에 넘길 수 있다.
**한 번에 끝까지 돌리기** (2026-11-17 추가, 확장 0.4.0)

한 단계씩 하는 방식은 그대로 두고, 시작할 때 고를 수 있는 방식을 하나 더했다.

- AI가 중간에 묻는 것을 시작할 때 미리 받는다: 글의 목적, 바라는 말투, 읽은 사람이 했으면 하는 행동
- 그 뒤로는 단계를 차례로 돌린다. AI가 되묻는 단계에는 확장이 대신 답한다.

| 단계 | AI가 묻는 것 | 대신 보내는 답 |
|---|---|---|
| 2 | 지울 소제목 | AI가 추천한 대로 정리하라고 한다 |
| 3 | 목적, 말투, 유도할 행동 | 시작할 때 받은 값. 내 말투와 이미 쓴 글 제목도 여기에 붙인다 (7장) |
| 4 | 고칠지 말지 | 프롬프트가 정해 둔 말("수정해줘") |

- 대신 보내는 답은 프롬프트 묶음에 들어 있다. 원본은 `extension/scripts/extension-prompts.ts`다. 웹에는 없는 글이다.
- 진행 상황은 단계가 바뀔 때마다 저장한다. 멈추거나 오류가 나면 [이어서 끝까지 돌리기]로 멈춘 곳부터 이어서 한다. 이미 보낸 답은 다시 보내지 않는다.
- 스스로 멈추는 때: 사람이 [멈추기]를 눌렀을 때, AI의 답이 길이 한도에 걸려 잘렸을 때, 주소 단계에 쓸 제목을 찾지 못했을 때, 대신 보낼 답이 없는 단계를 만났을 때
- 끝난 뒤에 단계를 눌러 결과를 보고, 마음에 안 드는 단계만 다시 할 수 있다.
- 개요를 중간에 고칠 기회가 없고, AI를 한 번에 10번쯤 부른다는 점을 시작 화면에 적어 둔다.

- **알아 둘 점**: 1단계와 3단계의 프롬프트는 웹 검색을 해서 쓰라고 한다. 그런데 API로 부르면 AI는 검색을 하지 못한다 (웹의 API 방식도 같다). 그래서 AI가 적은 출처와 숫자는 실제와 다를 수 있다. 화면에 이 안내를 띄운다. AI의 검색 기능을 켜는 것은 나중에 정한다 (13장).

### 5.13 사진으로 리뷰 쓰기 (2026-11-18 추가, 확장 0.9.0에 만듦. 진짜 AI로는 아직 확인하지 못함)

내가 산 제품의 사진을 올리면, AI가 사진을 보고 리뷰 글을 쓴다. 사용자가 요청한 기능이다.

**흐름**

1. "사진 리뷰" 탭에서 사진을 고른다 (10장까지. 고른 순서가 사진 번호다).
2. 제품 이름을 적는다. 메모(가격, 산 곳, 쓴 기간, 좋았던 점, 아쉬운 점)와 구매 방식(내 돈 / 제공받음 / 말하지 않음)을 적는다.
3. [리뷰 글 만들기]: 사진마다 긴 쪽 1280픽셀의 JPG 사본을 만들어, 번호표("사진 1")와 함께 AI에 보낸다. 사진이 먼저, 프롬프트가 맨 끝이다.
4. AI의 답: `[제목]` 아래 제목 후보 3개, `[본문]` 아래 본문. 본문에는 사진 자리 `[IMG: 사진N - 설명]`이 들어 있다.
5. 확장이 사진 자리를 정리한다 (`arrangePhotos`): 한 줄에 하나씩 두고, 없는 번호·겹친 번호·내 사진이 아닌 이미지 자리는 지우고, AI가 빠뜨린 사진은 글 끝에 붙인다. 무엇을 고쳤는지 화면에 알려 준다.
6. [채우기로 보내기]: 글과 사진이 함께 채우기 탭으로 간다. 자리 이름("사진1")이 같은 곳에 사진이 미리 골라진다. 올리는 것은 4.3의 사진 넣기와 같다.

**지키는 것**

- **지어내지 않는다.** AI는 내가 실제로 써 봤는지 알 수 없다. 그래서 사진에 보이는 것과 메모에 적은 것만 사실로 쓰게 한다. 가격, 규격, 성능 수치, 쓴 기간, 느낀 점은 메모에 있을 때만 쓴다. 꼭 필요한데 모르는 내용은 "(확인 필요: …)"로 남기게 하고, 화면에서 몇 곳인지 알려 준다 (5.8과 같은 생각).
- **제공받은 제품은 밝힌다.** 구매 방식을 "제공받음"으로 고르면 글 첫머리에 밝히게 한다.
- **사진은 고른 AI 회사로만 간다.** [리뷰 글 만들기]를 눌렀을 때만, 작게 줄인 사본을 보낸다. 서버(Supabase)에는 올리지 않는다. 화면에 이 안내와 "얼굴, 주소, 송장이 찍힌 사진은 빼 달라"는 말을 둔다.
- 과장하는 말과 근거 없는 비교를 쓰지 않게 한다.

**내 말투**: 말투 카드가 있으면 프롬프트에 붙인다 (`voice.block`. SEO 8단계와 같은 조각). 체크로 끌 수 있다.

**프롬프트**: 확장에만 있는 글이다 (`scripts/extension-prompts.ts`의 `review.photo`, `review.photo_label`, `review.purchase_*`, `review.no_notes`). 묶음에서는 "없어도 되는 글"로 둔다. 예전 묶음을 받아 둔 사람은 다른 기능을 그대로 쓰고, 사진 리뷰 탭에서만 "프롬프트를 새로 받아 달라"는 안내를 본다.

**AI 호출**: `llmGenerate(prompt, opts, images)`. 회사마다 모양이 다르다.

| 회사 | 사진을 보내는 모양 |
|---|---|
| Claude | `{ type: 'image', source: { type: 'base64', media_type, data } }` |
| GPT | `{ type: 'image_url', image_url: { url: 'data:image/jpeg;base64,…' } }` |
| Gemini | `{ inline_data: { mime_type, data } }` |

고른 모델이 사진을 읽지 못하면 회사가 오류를 돌려준다. 그때는 다른 모델을 고르라고 안내한다.

**아직 없는 것**

- 다른 사람의 리뷰 글에서 배우기. 사용자가 말을 꺼냈다. 지금까지의 원칙은 "내 블로그 글만 배운다"였다. 남의 문장을 가져오면 베낀 글이 되기 때문이다. 넣는다면 사용자가 고른 글 몇 편에서 **구성만**(어떤 차례로 무엇을 다루는지) 뽑아 쓰고 문장과 표현은 가져오지 않는 방식을 제안했다. 정하지 않았다.
- 만든 리뷰를 기록에 남기기 (지금은 창을 닫으면 사라진다), 사진 없이 다시 만들기.
- 쇼핑몰 주소에서 제품 정보(이름, 가격, 규격) 읽어 오기.

## 7. 내 말투 (새로 추가)

지금은 "작성자 페르소나" 칸에 말투를 문장으로 직접 적는다. 이 칸을 내 글에서 자동으로 채운다.

### 7.1 내 글 모으기
- 내 블로그 글을 열고 [이 글을 말투 예시로 추가]를 누른다. 직접 붙여넣어도 된다.
- 10~20편을 모은다.
- **AI를 쓰기 전에 직접 쓴 글로 고른다.** AI가 쓴 글로 분석하면 AI 말투를 배운다.

### 7.2 말투 카드 만들기
- **AI가 정리하는 것**: 문장 끝맺음, 자주 쓰는 표현과 접속어, 글을 시작하고 끝내는 방식, 독자 호칭, 쓰지 않는 표현
- **코드가 세는 것**: 평균 문장 길이, 문단 길이, 줄바꿈 간격, 이모지·특수문자 빈도, 끝맺음 비율
- 만든 카드는 화면에 보여주고 사람이 고칠 수 있다.
- 한 사람이 여러 장을 둘 수 있다 (정보글용, 일상글용).

### 7.3 글 쓸 때 적용
- 말투 카드를 "작성자 페르소나" 자리에 넣는다.
- 짧은 예시 문단 2~3개를 곁들인다.
- 우선순위: **사실 > 글 구조(글쓰기 방식) > 내 규칙 > 말투**. 말투 때문에 숫자나 구조가 바뀌면 안 된다.

### 7.4 확인
- 생성된 글의 문장 길이와 끝맺음 비율을 말투 카드와 비교해 "말투 일치도"를 보여준다.
- 어긋나면 내용은 그대로 두고 말투만 다듬는 단계를 한 번 더 돌린다. 다듬은 뒤 숫자가 바뀌지 않았는지 코드로 확인한다.

### 7.5 주의
- 예시 글의 내용이 새 글에 섞이지 않게 한다. "말투만 참고하고 내용은 가져오지 말 것"을 규칙으로 넣는다.
- 예시에 경험담이 있으면 AI가 흉내 내 없는 경험을 만든다. 5.4의 사례 메모 규칙과 같이 적용한다.
- 내 글로만 만든다.
- 예시 글은 내 계정에만 저장되고, 분석할 때 내가 고른 AI로 전송된다.

### 7.6 첫 버전에서 실제로 만든 것 (2026-11-17, 확장 0.4.0)

사용자가 "한 번에 돌릴 때는 기존에 쓴 글을 계속 학습하면 좋겠다"고 해서, 말투 단계(V1, V2)의 일부를 먼저 만들었다.

**내 글 모으기**
- [내 말투] 탭에서 [내 블로그의 최근 글 찾기]를 누르면 최근 글 20편의 제목이 뜬다. 고른 글의 본문을 읽어 모아 둔다. 직접 붙여넣어도 된다.
- 최대 20편을 둔다. 넘으면 오래전에 넣은 글부터 뺀다. 200자가 안 되는 글은 넣지 않는다.
- 글과 말투 카드는 이 컴퓨터의 확장 저장소에만 둔다.

**블로그 글을 읽는 방법** (2026-11-17에 공개 블로그로 확인)
- 글 목록은 `PostTitleListAsync.naver`, 글 한 편은 `PostView.naver`에서 읽는다. 본문은 `.se-main-container` 안의 `p.se-text-paragraph`다.
- **확장 화면에서 직접 부르면 네이버가 막는다 (403).** 다른 곳에서 온 요청을 거절한다. 그래서 열려 있는 네이버 블로그 탭 안에 읽기 코드(`entrypoints/naver-reader.ts`)를 넣어서 읽는다. 새 권한은 필요 없다 (접근 허용 주소 `blog.naver.com`과 `scripting`).
- 로그인 정보를 싣지 않고 읽는다. 그래서 공개 글만 읽힌다.
- 내 블로그인지는 이렇게 안다: 글쓰기 화면의 주소에 있는 아이디는 내 것이다. 그 밖의 화면이면 "내 블로그가 맞나요?" 하고 한 번 묻는다.
- 네이버가 공개한 기능이 아니라서 모양이 바뀌면 읽지 못한다. 그때는 직접 붙여넣는다.

**말투 카드**
- 모아 둔 글 중 최근 12편(글마다 앞 1,500자)을 내가 고른 AI에게 보내 말투를 정리하게 한다. 정리하는 프롬프트는 묶음에 들어 있다 (`extension-prompts.ts`).
- 카드는 화면에서 고칠 수 있다. 사람이 고친 카드는 자동으로 덮어쓰지 않는다.

**계속 배우기**
- 한 번에 돌리기를 시작할 때, 설정이 켜져 있으면 내 블로그에서 새 글을 찾아 넣는다 (한 번에 최대 5편. 블로그 탭이 열려 있을 때만).
- 글 모음이 바뀌었으면 말투를 새로 정리한 뒤에 글을 쓴다 (AI를 한 번 더 부른다).
- 글을 쓸 때 3단계의 답에 말투 카드와 "이미 쓴 글" 제목(최대 30개)을 붙인다. 말투만 따르고 사실·숫자·사례는 가져오지 말라는 규칙을 같이 넣는다.

**7.1~7.4와 다른 점, 아직 안 한 것**
- 7.1은 "AI를 쓰기 전에 직접 쓴 글"만 넣으라고 한다. 새 글을 자동으로 넣으면 AI가 쓴 글도 들어간다. 그래서 설정으로 끌 수 있게 했고, 화면에 그 점을 적어 뒀다. 글마다 [빼기]가 있다.
- 코드가 세는 수치(문장 길이, 끝맺음 비율), 말투 일치도, 말투만 다듬는 단계, 카드 여러 장은 아직 없다.
- SEO 8단계에서는 세 방식 모두 말투를 쓸 수 있다. 한 번에 돌릴 때는 자동으로 붙이고, 한 단계씩 할 때는 초안 단계에서 [내 말투 넣기]를 눌러 답에 붙이고, 복사 방식에서는 [내 말투 복사]로 복사한다. 붙는 글은 셋 다 같다.
- 한 단계씩 하는 방식과 복사 방식에서는 새 글 찾기와 말투 다시 정리하기가 자동으로 돌지 않는다. [내 말투] 탭에서 직접 한다.
- 글쓰기 탭(방식 6개)에는 아직 붙이지 않았다.
- 서버의 `voice_profiles` 표는 아직 쓰지 않는다.

## 8. 로그인과 권한

**확장 로그인**
- 확장 안에서 이메일과 비밀번호로 로그인한다. 웹 로그인 화면이 이미 지원한다.
- 웹의 로그인 정보를 넘겨받아 같이 쓰지 않는다. 한쪽이 갱신하면 다른 쪽이 끊길 수 있다.
- 매직링크로만 가입한 사람은 비밀번호를 한 번 설정한다.

**가입과 프롬프트 보호**
- 확장을 배포하면 누구나 Supabase 주소와 공개 키를 볼 수 있다. 이 값은 원래 공개용이고, 데이터는 권한 규칙(RLS)으로 보호한다.
- 그래서 **아무나 가입할 수 없게** 해야 한다. 가입을 초대한 사람만 되게 하고, 프롬프트 표는 허용된 사용자만 읽게 한다.
- 배포 전에 모든 표의 권한 규칙을 한 번 점검한다.

**DB 접근**
- 확장은 로그인한 사용자 권한으로만 접근한다. 본인 글, 본인 말투 카드만 읽고 쓴다.
- 서비스 키는 확장에 넣지 않는다.

**실제로 만든 것 (2026-11-17, 확장 0.5.0)**
- 확장의 설정 탭에 이메일·비밀번호 로그인을 넣었다. 비밀번호는 로그인 요청에만 쓰고 저장하지 않는다. 로그인 정보(토큰)는 확장 저장소에 두고, 끝나기 전에 새로 받는다.
- **메일로 로그인 (0.5.1, 2026-11-18)**: 웹에는 비밀번호를 정하거나 바꾸는 화면이 없고, 사용자는 메일 링크로만 로그인해 왔다. 그래서 비밀번호 없이 로그인하는 방법을 확장에 넣었다.
  - [메일로 로그인 코드 받기]를 누르면 웹의 "메일 링크 로그인"과 같은 메일이 간다. 새 계정은 만들지 않는다 (`create_user: false`).
  - 메일에 온 6자리 코드를 적어 로그인한다. 코드는 Supabase의 "Magic Link" 메일 양식에 `{{ .Token }}`이 들어 있어야 온다. 양식을 바꾸는 것은 Supabase 화면에서 사람이 한다.
  - 양식에 코드가 없으면, 메일에 있는 링크의 주소를 복사해 붙여넣어도 로그인된다 (주소 안의 한 번 쓰는 표시로 확인한다). 링크를 눌러 버리면 그 표시는 웹 로그인에 쓰여서 못 쓴다.
  - 실제 서버가 두 방식의 요청을 받아 주는 것은 틀린 값으로 확인했다 (둘 다 "만료됨"으로 거절). 진짜 메일로 로그인하는 것은 사용자가 확인해야 한다.
- **메일의 링크를 누르면 로그인 (0.5.2, 2026-11-18)**: 0.5.1의 방법은 실제로는 쓰이지 않았다. 서버 기록을 보니 사용자는 확장에서 메일을 요청한 뒤 메일의 링크를 그냥 눌렀다 (웹에서 늘 하던 대로). 링크는 웹으로만 이어졌고 확장은 아무것도 받지 못했다. 주소를 복사해 붙여넣으라는 안내는 부자연스러웠다. 그래서 링크를 누르는 것만으로 로그인되게 바꿨다.
  - 확장에서 요청한 로그인 메일의 링크를 누르면, 서버는 로그인 정보를 주소의 `#` 뒤에 붙여 blog_studio 웹(Site URL)으로 보낸다. 웹은 그 정보를 쓰지 않고 로그인 화면으로 넘기는데, `#` 뒤는 그대로 따라온다 (기록과 웹의 응답으로 확인).
  - 확장의 배경 코드가 그 탭의 주소를 보고 로그인 정보를 받아 간다 (`tabs.onUpdated`). 그 뒤 탭을 "확장에 로그인됐어요" 화면으로 바꾼다. 이를 위해 접근 허용 주소에 웹 주소 하나를 더했다 (`.env`의 `WXT_WEB_URL`).
  - 지키는 것: 확장에서 메일을 요청하고 30분 안일 때만 받는다 (웹에 로그인하려던 링크는 건드리지 않는다). 받은 정보가 아까 적은 이메일의 계정인지 서버에 물어 확인한다. 받은 정보는 바로 새것으로 바꿔 받아서, 주소에 남은 것이 다시 쓰이지 않게 한다.
  - 알려진 한계: 다른 브라우저나 다른 크롬 프로필, 휴대폰에서 링크를 누르면 확장이 받지 못한다. 그때는 주소 붙여넣기를 쓴다.
  - 이 흐름은 가짜 저장소와 가짜 서버로 시험했다 (`tests/session.test.ts`). 진짜 메일의 링크로는 사용자가 확인해야 한다.
- **비밀번호 정하기 (0.5.1)**: 로그인한 뒤 같은 카드에서 비밀번호를 새로 정할 수 있다. 웹의 비밀번호 로그인에도 같은 비밀번호가 쓰인다. 웹에 비밀번호 화면을 만드는 일은 하지 않았다.
- 가입은 지금 누구에게나 열려 있다. 초대제로 바꾸지는 않았고, 프롬프트 표를 허락 목록으로 막았다 (5.3).
- 지금 로그인으로 하는 일은 프롬프트 받기뿐이다. 만든 글 저장, 업종 설정 받기, 발행 묶음은 아직이다.

**확장 권한 (manifest)**

| 권한 | 이유 |
|---|---|
| `sidePanel` | 사이드 패널 |
| `storage` | 로그인 정보, AI 키, 견본 부품 |
| `scripting` | 글쓰기 탭에 채우기, 열린 탭의 본문 읽기 |

- 네이버 비밀번호와 쿠키는 다루지 않는다.

## 9. DB와 파일 변경 (제안)

### 9.1 새 표

**`publish_packages`** (발행 묶음)

| 칸 | 내용 |
|---|---|
| `id`, `user_id`, `blog_post_id` | 누구의 어떤 글인지 |
| `title`, `blocks`, `tags` | 확정된 제목, 블록 목록, 태그 |
| `images` | 자리별 이미지: 자리 이름, 종류, Storage 경로, 설명, 출처 표기 |
| `warnings` | 변환 경고 |
| `state` | `needs_check`(확인 필요) → `ready`(준비됨) → `filled`(채움) 또는 `drafted`(임시저장됨) → `scheduled` 또는 `published` |
| `fill_step` | 어디까지 채웠는지 (글, 이미지). 이어 하기에 쓴다 |
| `scheduled_at`, `naver_post_url`, `published_at` | 발행 기록 |

**`prompt_templates`** (프롬프트)

| 칸 | 내용 |
|---|---|
| `key` | `common`, `method_1` … `method_6` |
| `version`, `body`, `updated_at` | 버전, 본문 |

**`voice_profiles`** (말투 카드)

| 칸 | 내용 |
|---|---|
| `id`, `user_id`, `name` | 누구의 어떤 카드인지 |
| `card` | AI가 정리한 말투 특징 (사람이 고칠 수 있음) |
| `stats` | 코드가 센 수치 |
| `samples` | 짧은 예시 문단 |
| `source_urls` | 예시 글 주소 |

**`topic_queue`** (글감 대기열)

| 칸 | 내용 |
|---|---|
| `id`, `user_id` | 누구의 주제인지 |
| `input` | 주제, 독자 상황, 한줄 메모, 글쓰기 방식(자동 또는 지정), 업종, 말투 카드 |
| `status` | `queued`(기다림) → `generating`(만드는 중) → `done`, `duplicate`(겹침), `failed` |
| `run_where` | 확장에서 만들지, 서버에서 만들지 |
| `blog_post_id`, `error` | 만들어진 글, 실패 이유 |
| `created_at`, `started_at`, `finished_at` | 시각 기록 |

사람마다 두는 설정(대기열 실행 위치, 하루 생성 상한, 자동 임시저장 켜기와 하루 상한)은 사용자 설정 표에 둔다.

**`writing_rules`** (내 규칙)

| 칸 | 내용 |
|---|---|
| `user_id` | 누구의 규칙인지 |
| `body`, `updated_at` | 규칙 메모, 고친 시각 |

- 권한: `publish_packages`, `voice_profiles`, `writing_rules`, `topic_queue`는 본인만 읽고 쓴다. `prompt_templates`는 허용된 사용자만 읽고, 관리자만 쓴다.
- 기존 `jobs` 표와 에이전트용 규칙은 건드리지 않는다.
- `blog_posts`에 칸을 더한다: 자료 출처(주소, 가져온 날짜), 사용한 말투 카드, 확인필요 항목과 답, 검수 카드 결과.

### 9.2 Storage
- 비공개 버킷 `publish-images`, 경로는 `사용자ID/묶음ID/자리.png`. 본인 폴더만 읽고 쓴다.

### 9.3 웹
- `web/lib/core/`: 공용 코드 (5.2)

## 10. 개발 단계

### 발행 (E)

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| **E0** 뼈대 | 확장 프로젝트, 사이드 패널, 로그인 | 크롬을 껐다 켜도 로그인이 유지됨 |
| **E1** 에디터 읽기 | 문서 구조 읽기, 견본 저장 | 견본 글의 부품 종류가 패널에 보임 |
| **E2** 기본 채우기 | 제목, 문단, 굵게·기울임·밑줄, 정렬, [복사하기], 팝업과 기존 글 감지 | 임시저장 후 다시 열어도 그대로임. "작성 중인 글" 팝업이 있으면 멈추고 알려 줌 |
| **E3** 서식 채우기 | 소제목, 인용구 3종, 구분선 3종, 표 | 실제 글 견본 전부가 임시저장 후에도 그대로임 → **성공 기준** |
| **E4** 웹 연결 | `publish_packages`, [확장으로 보내기], 글 목록 | 웹에서 보낸 글이 패널에 뜨고 채워짐 |
| **E5** 이미지 넣기 | 내려받기, 붙여넣기, 자리 옮기기, 이어 하기 | 이미지 5장짜리 글이 자리에 맞게 들어감. 중간에 실패하면 이미지 단계만 다시 할 수 있음. **0.6.0에 내 컴퓨터의 사진으로 만듦. 실제 화면 확인은 아직** |
| **E6** 이미지 준비 | 자리별 이미지 선택, 블로그용 카드 | 이미지 자리를 카드·사진·업로드로 채워 보낼 수 있음. **0.7.0에 블로그용 카드(표지, 소제목 요약)를 만듦. 미리보기에서 확인함** |
| **E7** 발행 기록 | 태그 복사, 글 주소 기록, 예약 표시 | 발행 후 웹 글 목록에 주소가 보임 |
| **E8** 가족 배포 | 설치 안내서 (아래 "가족용 안내서 형식"), 가입 초대 | 가족 1명이 안내서만 보고 글 1편을 올림 |

### 글쓰기 (G)

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| **G0** 공용 코드 | `web/lib/core/`로 모으기, AI 연결 손보기 (6.4) | 웹의 글 생성이 전과 같은 결과를 냄. 최신 모델로도 오류가 없음 |
| **G1** 키 안내 | 키 카드 3개, 확인, 사용량 | 키가 없는 사람이 안내만 보고 Gemini 키를 넣어 확인까지 통과함 |

### 말투 (V)

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| **V1** 예시로 적용 | 예시 글을 붙여넣어 말투 반영 | 같은 주제를 기본 말투와 내 말투로 만들었을 때 차이가 보임 |
| **V2** 말투 카드 | 분석, 수치 세기, 보기·고치기 | 카드를 고치면 다음 글에 반영됨 |
| **V3** 내 블로그에서 가져오기 | [이 글을 말투 예시로 추가] | 블로그 글 10편을 버튼으로 모을 수 있음 |
| **V4** 일치도와 다듬기 | 일치도 표시, 말투만 다듬기 | 다듬은 뒤에도 숫자가 바뀌지 않음 |

### 대기열 (Q)

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| **Q1** 글감 대기열 (확장) | 주제 여러 개 넣기, 차례로 만들기, 하루 상한, 겹침 확인, 알림 | 주제 5개를 넣고 자리를 비우면 글이 발행 대기에 쌓여 있음. 상한에 닿으면 멈춤 |
| **Q2** 서버에서 만들기 | 웹의 대기열 화면, 서버 실행기 | 폰에서 주제를 넣으면 컴퓨터가 꺼져 있어도 글이 만들어짐 |
| **Q3** 자동 임시저장 (선택) | 켜기와 안내문, 새 탭에서 채우기, 임시저장, 저장 확인, 멈추는 조건 | 켜 두면 준비된 글이 하루 상한 안에서 임시저장함에 들어감. 발행은 되지 않음. 팝업이나 로그인 풀림이 있으면 멈추고 알림 |

### 추천 순서
1. **E0 → E1 → E2 → E3** (성공 기준 확인)
2. E4, E7 (웹과 연결, 발행 기록)
3. G0, G1 (공용 코드, 키 안내)
4. G2, G3, G5, G6 (확장에서 글쓰기, 검수)
5. E5, E6 (이미지)
6. Q1, Q2 (글감 대기열)
7. V1, V2 (말투)
8. Q3 (자동 임시저장, 선택)
9. G7, E8, G4, V3, V4

E1~E3은 DB 없이 진행한다. 패널에 시험용 블록 목록을 붙여넣어 채운다.

### 시험 방법
- **견본 글 세트**: 실제 글 7개와, 모든 서식을 한 번씩 넣은 글 1개를 고정해 둔다.
- **왕복 확인**: 채우기 → 임시저장 → 새로 열기 → 문서를 다시 읽어 블록 목록과 코드로 비교한다.
- **눈으로 확인**: PC 화면과 모바일 미리보기에서 소제목, 표, 이미지 위치를 본다.
- **글쓰기 비교**: 고정한 입력 5개를 웹과 확장에서 만들어 검증 결과가 같은지 본다.
- 채울 때마다 에디터 버전을 기록한다.

### 가족용 안내서 형식
- 단계마다 걸리는 시간을 표로 적는다 (설치, 로그인, 키 넣기, 첫 글).
- 자주 막히는 곳을 "증상, 원인, 해결" 표로 적는다. 가족이 실제로 막힌 곳을 계속 더한다.
- 운영 수칙을 넣는다:
  - 본인 계정으로만 쓴다.
  - 하루 1~2건 정도만 올린다.
  - 발행 전에 한 번 읽는다.
  - 내가 찍은 사진을 먼저 쓰고, 인터넷 이미지는 가져오지 않는다.
  - 겪지 않은 일은 사례 메모에 적지 않는다.

## 11. 위험과 대응

| 위험 | 대응 |
|---|---|
| 네이버가 에디터를 바꿔 채우기가 고장 남 | 채우기 전 확인, [복사하기], 견본 다시 읽기, 버전 기록 |
| 채운 내용이 저장되지 않음 | 채운 뒤 다시 읽어 검증, 왕복 확인 |

| 써 둔 글을 덮어씀 | 기존 글이 있으면 묻기 |
| 프롬프트가 밖으로 나감 | 확장 파일에 넣지 않기, 초대제 가입, 프롬프트 표 읽기 제한. 로그인한 사람은 볼 수 있음을 감안 |
| AI 키가 새어 나감 | 내 PC에만 보관, 웹페이지 접근 차단, 기록에 남기지 않기, 월 한도 안내 |
| 생성 중 패널을 닫아 중단됨 | 경고 표시, 입력 내용 보관 |
| 웹과 확장의 결과가 달라짐 | 공용 코드 한 벌, 글쓰기 비교 시험 |
| 예시 글의 내용이 새 글에 섞임 | "말투만 참고" 규칙, 숫자 검사 |
| AI가 쓴 글로 말투를 배움 | 직접 쓴 글을 고르라고 안내 |
| AI가 경험담을 지어냄 | 사례 메모가 있을 때만 경험담 허용 |
| 확인하지 못한 숫자가 글에 남음 | 확인필요 표시, 표시가 남으면 채우기 차단 |
| 많이 올려서 계정에 문제가 생김 | 하루 1~2건 권장을 안내서와 화면에 표시. 발행량은 사람이 조절 |

| 자동 임시저장이 쓰던 글을 덮어씀 | 확장이 연 새 탭만 사용, "작성 중인 글" 팝업이 뜨면 닫지 않고 멈춤 |
| 대기열이 글을 너무 많이 만들어 비용이 늘어남 | 하루 생성 상한, 오늘 사용량 표시 |
| 대기열이 비슷한 글을 반복해서 만듦 | 만들기 전에 최근 글과 주제 겹침 확인 |
| 서버에서 만들려면 키를 서버에 둬야 함 | 사람마다 고르게 함. 키 저장 방식은 13장 8번에서 정함 |
| 카드 속 숫자가 본문과 다름 | 코드로 대조, AI 다시 쓰기 끄기 |
| 무료 사진·AI 이미지의 사용 조건 | 출처 표기 저장, 다른 블로그·뉴스 사진은 쓰지 않음 |
