# 공통 온톨로지 (Common Ontology) — 6개 방식 전부 공유

> 이 파일은 6개 방식 프롬프트 앞에 **반드시 삽입**되는 공통 베이스입니다.
> `01~06` 각 방식 파일은 이 공통 블록 뒤에 **방식 특화 확장**만 덧붙입니다.

```
═══════════════════════════════════════════════
[공통 온톨로지 A] 도메인 지식 구조
═══════════════════════════════════════════════

## Class: 주제도메인
├─ 속성(Property)
│  ├─ 주제명, 핵심대상, 발생배경
│  ├─ 주요용어 (domain-specific terms)
│  └─ 관련법령/규칙/표준 (있는 경우)
│
├─ 사실요소(SubClass)
│  ├─ 정량데이터: {금액, 수치, 기간, 비율}
│  ├─ 정성요소: {장점, 단점, 주의사항}
│  └─ 주체/기관: {주관기관, 수혜대상, 관련기업}
│
├─ 조건요소(SubClass)
│  ├─ 적용조건: 해당 내용이 성립하는 상황
│  ├─ 예외조건: 성립하지 않는 케이스
│  └─ 가점/우대: 유리한 조건
│
└─ 제외요건(SubClass) ★ 신뢰성 핵심
   ├─ 대상제외: 명백히 해당 안 되는 케이스
   ├─ 반려/실패사례
   └─ 오해/오류 포인트

## 지시
입력된 {도메인정보}를 위 구조로 분해/정리하라.
누락 정보는 "확인필요" 태그로 식별하고, 추측으로 채우지 말 것.

═══════════════════════════════════════════════
[공통 온톨로지 B] 독자 상태 (Awareness Level)
═══════════════════════════════════════════════

## Class: 독자인지단계
├─ L1 (인지형): 주제 존재 자체를 모름
│  └─ 콘텐츠 전략: "이런 게 있습니다" 인지 확산형
│
├─ L2 (자격진단형): 존재는 알지만 본인 대상인지 모름
│  └─ 콘텐츠 전략: "당신이 해당되는지 확인해드립니다"
│
├─ L3 (절차형): 대상인 건 아는데 방법을 모름
│  └─ 콘텐츠 전략: "이렇게 진행하세요"
│
└─ L4 (심화형): 경험했는데 실패/불만족
   └─ 콘텐츠 전략: "이런 이유로 실패하고 이렇게 대처하세요"

## Class: 독자고민(Pain) — 인지단계별 다름
├─ L1 Pain: 정보 부재, 시작점 모름
├─ L2 Pain: 자격요건 해석 모호, 선택 장애
├─ L3 Pain: 서류/절차 부담, 실수 우려
└─ L4 Pain: 반려 사유 파악, 재도전 방법

## 지시
입력된 {target_awareness_level}(L1~L4)을 기반으로
독자 고민 3개를 도출하고, 이를 소제목 골격에 매핑할 것.

[공통 온톨로지 C] 네이버 C랭크 SEO
═══════════════════════════════════════════════

## Class: SEO신호
├─ 전문성신호(E-E-A-T)
│  ├─ 주제집중도: 같은 카테고리 글 누적
│  ├─ 경험노출: 1인칭, 실제 사례
│  ├─ 출처인용: 공식기관, 법령, 공고문, 통계
│  └─ 구체수치: 금액/%/기한/건수 등
│
├─ 체류신호
│  ├─ 구조화: 비교표, 체크리스트, 순서도
│  ├─ 질문삽입: 중간 Q&A
│  └─ 가독성: 단락 3줄 이내, 모바일 친화
│
└─ 키워드신호
   ├─ 메인키워드: 제목 앞 15자 + 첫 100자 + 마지막 문단
   ├─ 서브키워드: 소제목에 분산
   └─ LSI키워드: 본문 자연 배치

## 공리(강제규칙) — 공통 10개
1. 메인키워드 총 등장 3~5회 (초과 시 스팸 간주)
2. 이미지 내 정보는 반드시 본문 텍스트로 중복 기술
3. 최소 1,500자 이상 (이미지 의존 금지)
4. 구체수치 최소 5개 이상 (금액/%/건/명 등)
5. 경험/사례 언급 최소 2회 이상 (1인칭 또는 3인칭 케이스)
6. 공식기관명/출처 최소 3회 (기관, 법령, 통계, 공고)
7. 제외요건/반대사례 최소 1개 명시 (★신뢰성 핵심)
8. 비교표 + 체크리스트 각 1개 이상
9. 키워드 자연 배치 (억지 삽입 금지)
10. AI티 나열식 금지 ("첫째/둘째/셋째..." 반복 패턴 배제)

## 작성자 정체성 변수
- {author_identity}: 작성자 정체성 (예: "공공조달행정사", "경영컨설팅 전문가")
- {consultancy_name}: 소속명 (예: "오너스경영연구소")

## 반영 규칙 (brand_voice 값이 제공될 때)
1. 도입부에 작성자 정체성 1회 자연 노출
   예: "공공조달행정사로 일하면서 가장 많이 받는 질문이..."
2. 컨설팅 경험 언급 시 소속명 사용
   예: "저희 오너스경영연구소에서 실제로 진행한 케이스..."
3. 마무리 CTA에 정체성 + 소속명 조합
   예: "상담이 필요하시면 공공조달행정사로서 함께 도와드리겠습니다"
4. 과도한 반복 금지: 글당 각 2회 이하
5. brand_voice 값이 없으면 이 섹션은 완전히 생략 (일반 글로 작성)
6. `{author_identity}` 또는 `{consultancy_name}`이 빈 문자열("")로 치환되어 들어온 경우에도 brand_voice 미제공으로 간주하고 위 5번 규칙을 적용한다 (어색한 빈 자리 만들지 말 것)

STEP 5. 콘텐츠 생성
